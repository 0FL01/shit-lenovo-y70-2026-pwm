# Lenovo XT2611-1: реальный OLED PWM

## Старт
- Общение — на русском. Сначала WORKSTATE.md, затем только материалы выбранной задачи.
- Этот файл — правила; WORKSTATE.md — актуальные наблюдения и маршрут. WORKSTATE_HISTORY.md, старые планы и отчёты — история, не новые разрешения.
- 00-facts/ содержит датированные наблюдения; не принимай их за текущие настройки устройства.

<a id="definition-of-done"></a>
## Цель и завершение
- На дневной и вечерней яркости подтвердить либо несущую ≥2000 Гц без глубокой низкочастотной огибающей, либо DC ниже целевой границы модуляции 3–5% без низкочастотного chop. Это личное требование владельца, не медицинский порог.
- Дополнительно нужны принятие владельцем для постоянного использования и проверенное временное управление со штатной яркостью, lifecycle и откатом. Сборка, меньше полос и отчёт о блокере не заменяют результат.
- Постоянный KernelSU-Next уже установлен; не повторять unlock/root как этап исследования и не подменять root-проект.

## R&D
- План — GPS: меняй порядок, методы и состав веток внутри цели и разрешений. Полная картография и закрытие всех веток не обязательны.
- Выбирай различающий опыт по пользе для решения, цене и риску. До него кратко запиши вопрос, достаточный контроль и границы операции. При смене протокола отделяй данные до/после, не подгоняй критерий под результат.
- При застое меняй метод или ветку. Возвращаться к закрытой гипотезе можно с новым основанием, но это не возобновляет старое аппаратное разрешение.
- После значимого результата — один checkpoint: факт → вывод → изменение маршрута → ближайший вариант. Специализированный документ обновляй, только если изменился его вывод; отчёт по сводкам не размножай.

## Границы операций
- Автономно разрешены диагностика, съёмка и обратимые штатные настройки. Новые DSI-последовательности, flash и изменения AVB/слотов требуют точного отдельного согласования; принятие риска повреждения не заменяет его.
- Перед аппаратной операцией проверь актуальные identity/build/panel и исходное состояние; сохраняй Enforcing. Для нового образа — RAM-first при проверенной поддержке; до записи раздела обязательны совместимость, проверенный оригинал и путь возврата. Физическое восстановление не предполагать. Бэкап пользовательских данных не является условием.
- Один писатель панели; до другой DDIC-пробы останови applier с проверкой. По умолчанию применение сессионное с возвратом; оставить без автоматического отката можно по отдельному прямому запросу. Persistence — явный opt-in, Remember после reboot по умолчанию не отмечен, штатный reset очищает его.
- Не переносить команды Pixel на BOE; образы XT2611-3 — только для офлайн-сравнения, пока совместимость не доказана.
- Проба глазами — после технического допуска либо по отдельному прямому запросу владельца; это не доказательство Гц. При дискомфорте прекратить, не провоцировать симптомы.
- Факты отделяй от сообщений владельца, гипотез и unknown; метки реестра — в 00-facts/claims.yaml. Подтверждение по источнику не равно подтверждению на цели.
- Контраст RAW, readback и refresh не доказывают физические Гц или отсутствие огибающей. Сохраняй stock и лучший проверенный промежуточный baseline в сопоставимых условиях; не выдавай улучшение метода за улучшение панели.
- Не публиковать адреса, серийники, токены и приватные RAW. Приватные материалы — в соседней legion-y70-lab/. Отчёты и исходники не хешировать без конкретной причины; предлагаемые образы и проверяемые бинарники идентифицировать.
