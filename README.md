# XT2611-1 PWM research: atomic agent context pack

**Цель:** исследовать возможность реального изменения частоты PWM OLED-панели Lenovo Legion Y70 New Generation (2026), `XT2611-1`, hardware `pvt`, на глобальной прошивке Motorola Edge 70 Max; при наличии доказательств подготовить минимальный обратимый патч и воспроизводимый образ для согласованного теста.

Дата фиксации внешних источников: **2026-10-28**. Это **исследовательский пакет, а не готовый PWM-fix или образ прошивки**.

## Быстрый запуск агента

1. Открой папку в своём E2E coding-agent окружении. Корневой `AGENTS.md` задаёт ограничения и ожидаемые артефакты.
2. Дай агенту промпт из `PROMPT_FOR_AGENT.md`. Агент самостоятельно исследует, пишет код, тесты и отчёты; от владельца нужны только доступ к устройству и физические тесты.
3. По возможности подключи телефон по ADB. Скрипт `06-tools/collect_readonly.sh` выполняет только чтение: системные настройки и содержимое разделов остаются неизменными.
4. Начинай с `T01` и проходи контрольные точки этапа перед применением собранного образа. Все неразрешённые факты документируются как unknown.

## Файлы и назначение

- `AGENTS.md`: правила работы агента, границы автономности, ожидаемые результаты.
- `00-facts/device.yaml`: точно известные сведения о физическом устройстве и неизвестные параметры.
- `00-facts/claims.yaml`: атомизированные внешние утверждения с уровнями достоверности.
- `01-evidence/sources.md`: ссылки на проверенные первоисточники и наблюдения.
- `02-pixel/hk3_case.md`: механика Pixel 8 Pro с точными семантическими элементами коммита; что переносимо и что нет.
- `03-investigation/firmware.md`: варианты региональных ROM и безопасный план их дифференциального анализа.
- `03-investigation/code-search.md`: карта драйверов, пути, сигнатуры, методы трассировки команд.
- `03-investigation/hypotheses.md`: гипотезы с условиями подтверждения и остановки.
- `04-tasks/tasks.yaml`: атомарные задачи, входы/выходы и зависимости.
- `04-tasks/acceptance.md`: критерии выполненности каждого исследовательского этапа.
- `05-safety/gates.md`: контрольные точки записывающих операций, разметка A/B и обязательный откат.
- `05-safety/optical_measurement.md`: объективная проверка реальной частоты PWM.
- `06-tools/collect_readonly.sh`: безопасное снятие доступных без root сведений с телефона.
- `06-tools/scan_workspace.sh`: read-only первичная индексация распакованных исходников и ROM.
- `WORKSTATE.md`: журнал для передачи контекста между сеансами агента.

## Конкретный вопрос, на который надо ответить

**Есть ли у фактически установленной OLED-панели `XT2611-1` команда/режим, меняющий частоту PWM, и на каком уровне он программируется: panel DSI commands, Device Tree, kernel driver, Display HAL или firmware?**

Допускается результат «не найдено» или «невозможно без закрытой документации». Отчёт должен объяснять, что проверено, и не маскировать программное затемнение или частоту обновления дисплея под изменение физической частоты PWM.

## Важные заблуждения, которые надо отсеять

- `167 Hz` для глобального Edge 70 Max и `720 Hz` в рекламно-обзорных описаниях китайского Y70 не означают автоматически разные конфигурации панели. Это могут быть разные составляющие оптического сигнала и методики измерения.
- `BOE Q10` описывает материал/семейство панели в обзорах; **не подтверждает точную модель panel IC, revision или DSI register map установленного экземпляра**.
- Репозиторий ядра по тегу для `XT2611-1` подтверждает публикацию исходников, но **не гарантирует**, что весь нужный display driver, Device Tree и closed-source HAL вошёл в релиз.
- Команды Pixel 8 Pro специфичны для Samsung HK3 в Exynos display stack, а наш целевой аппарат использует Qualcomm; нельзя копировать байтовую команду на него.
- `Flicker prevention` уже включён владельцем без заметного эффекта. Не предлагать его снова как решение, но разобраться с его внутренней реализацией.

## Принцип

**Research -> evidence -> reproducible source build -> reversible inactive-by-default patch -> bench/measurement -> отдельный подтверждаемый владельцем этап записи на устройство.**
