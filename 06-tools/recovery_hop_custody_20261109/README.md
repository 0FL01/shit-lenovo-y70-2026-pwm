# Typed per-hop recovery evidence reducer — inert model only

2026-11-09. `custody_model.py` provides executable pure functions plus frozen dataclasses/enums. No sockets/proc/pidfd/device/file readers, transports, command strings, subprocess, dispatch, runtime imports or production changes. It imports only dataclasses and enum. C336dd969 remains published, STOCK15 HOLD, unknown14 disabled; original37/45/8/60/600 protocol is not replaced by this model.

## Concrete boundary, not a stronger invented contract

The model separates four ordered hops: client→local forward; authenticated SSH session; remote destination socket→ADB server; server transport→physical device. Each has its own host boot/native monotonic time domain and exact expected task/executable/socket/namespace/session/server-epoch bindings. The last additionally binds device identity and boot. Numbers from different clocks are NEVER subtracted. No topology of the current live host is invented.

Separate HopVerdict fields:
- `task_lifetime`: externally qualified, gapless held PID-object/process lifetime evidence through assessment time, NOT immutable task_struct identity. A properly acquired nonretargeting pidfd/proc handle may support this narrower fact; fresh numeric PID does not. Linux v6.12 de_thread nonleader exec can transfer leader PID/starttime association: https://github.com/torvalds/linux/blob/v6.12/fs/exec.c#L1094-L1111 . Exact host kernel/config is unknown, so this remains reference semantics, not a host qualification. Neither equal PID/starttime nor held handle proves unchanged executable. ESRCH is not uniquely task-gone: LSM/seccomp/error provenance must be resolved separately. Unknown cause stays stopped.
- `connection_lifetime`: same held connection object over the specified interval. An open numeric FD alone is insufficient; lifetime/identity/close/reuse provenance must be qualified. SSH hop also needs its own authenticated-session snapshot.
- `executable_snapshot` and `holder_snapshot`: fresh exact original scoped association evidence. A held old exe file descriptor does not freeze the task's current executable. Holder snapshot remains a snapshot, not universal all-thread/namespace/hidden-holder uniqueness.
- `continuous_custody`: OPTIONAL informational true only for separately qualified continuous executable+custody evidence. It is false in the positive fixture and is NOT imposed as a new universal admission guard. No actual reader for this capability is claimed.
- `physical_identity`: fresh independently qualified device-identity evidence joined to the same server/transport binding snapshot. A transport ID by itself is neither physical identity nor continuity across server replacement. A server/transport ID reuse or new holder/exec/custody-gap fault is terminal if observed.

Local UNIX SO_PEERCRED is an optional fact about ONLY the socket peer for that Unix hop at connect. It never fills remote ADB/socket/physical-device gates. TCP snapshots do not become peer credentials or continuous sole-holder evidence. The model explicitly refuses to let PIDFD_LIVE+HELD_CHANNEL or UNIX_PEERCRED substitute for missing executable/holder/physical association.

**Actual existing blocker:** the original scanner/process-association guard failed with unresolved/masked cause. A held task and retained socket cannot supply the missing successful scoped association evidence or classify that failure as harmless nonserver exit. Old adapter stays terminal; later snapshots do not cure UNKNOWN or denial. This model permits only the narrow hypothetical `VERIFIED_NONSERVER_EXIT` incident with externally reviewed exact attribution, independently approved recovery route and all original scoped association checks. Current incidents remain UNRESOLVED. This is not a claim that all separately authorized physical operator recovery routes are impossible; they are outside this reducer.

Read the [AOSP smart-socket reference](../../artifacts/prebound_recovery_model_20261109_01/AOSP_PROTOCOL_REFERENCE.md): preselected/reserved smart channels are plausible reference transitions, but tracker/version/consumed-service sockets cannot be reused arbitrarily. The present model does NOT implement ADB reserve/tracker state machines, idle lifetime qualification, serving-build correspondence or socket refill. Every admitted operation/evidence epoch is one-use; a concrete implementation must map it to separately qualified available one-shot channel resources. No reconnect/refill/repin follows.

## Reader interface agreement

The [historical identity-bound reader01 assessment](../../artifacts/identity_bound_reader_20261109_01/ASSESSMENT.md) provides: injected acquire/read_stat/close, held proc-dir+pidfd/live-stat bracket. Its RootPin(fd/dev/ino/mode/pid_namespace/evidence_id) is a prerequisite, not authentication. Its current bounded events are stage/type/errno, not signed provenance or time-domain custody receipts. **Do not feed those events directly into admission.** A future separately reviewed adapter would need capture/source identity, task binding, local monotonic brackets, ownership/close outcomes and exact declared snapshot scope. Task proof cannot auto-fill executable, socket holder, SSH or physical evidence.

Observation carries hop, Domain, start/end, exact Binding, Capability, reader/source/qualification IDs, capture digest, sequence, evidence_nonce and Fault. Fixed RouteContract declares expected source/identity/clock and qualified reader-capability tuples before observations; never learn accepted pins from captures. Every observation is checked, including faults not used for a positive verdict. Duplicate/reordered/stale/future/cross-domain/binding-mismatched observations fail closed. Snapshot freshness is separately bounded; lifetime intervals must cover the full specified interval through dispatch assessment. A missing interval is not patched by two end snapshots.

**Provenance/authenticity limit:** frozen dataclasses, IDs and hashes provide structural binding and immutability, NOT signatures or authentication. Qualifications, expected pins, clock readings, independent review, authority and RebootProof are external trusted premises in synthetic tests. This module cannot certify the collector or convert untrusted caller-supplied facts into physical authority. No production-qualified reader is registered here. Captured bytes/source hashes must be authenticated and retained by a separate acquisition contract before real use.

## Public API and one-shot reducer

- `assess_route(contract, evidence: tuple[Observation,...], now_by_domain: tuple[(Domain,int),...]) -> RouteVerdict`. Verdict includes original observations and clock binding for re-evaluation. It preserves separate facts rather than merging task/exec/channel/device identity.
- `Request(incident, route_id, evidence_nonce, operation_id, component, physical_id, action)`; Action is finite READ_STATUS, REBOOT_TARGET, RESTORE_TARGET, STOP_CAMERA, RESTORE_CAMERA, RELEASE_OWNER. No experiment/DSI/shutter/root-operation vocabulary.
- `Authority(request, independent_recovery_approval_id)` must match the exact request, not generic experiment permission.
- `RecoveryState` includes immutable incident/source, old_route_id, mandatory old_adapter_terminal=True, queue uncertainty/original boot, incident classification/explanation, consumed operation/evidence sets, pending request and terminal reason. Use keyword fields; test fixture gives a complete example.
- `admit(state,request,authority,route,verified_reboot=None,*,dispatch_now_by_domain) -> (new_state,Decision)` recalculates evidence with dispatch-time clocks and checks exact source/incident/route/component/physical/evidence binding. Accepted Decision has source_digest and `admitted_model_only=True`, which authorizes nothing outside fake tests. Route failure latches terminal state; a later clean snapshot cannot heal it. Denied/unknown incident cannot be admitted.
- Admission consumes operation_id AND evidence_nonce before hypothetical dispatch and marks pending. `complete(state,request,Outcome.SUCCESS|DENIED|UNKNOWN)` matches exactly one pending request. DENIED/UNKNOWN terminal; success cannot erase an existing terminal condition. Reboot request success is not reboot verification. No automatic repeat with new operation ID over used evidence.
- With uncertain target queue, target restore/owner release requires a different same-target boot bound to the admitted route, original boot, independent verification receipt, boot_completed and full identity/root/Enforcing/module/panel/stock predicate. No DSI or settings restoration is issued by this model. Camera stop/restore is independently scoped; target reboot cannot satisfy camera state.

The consuming fake bridge must retain the returned latest immutable state. Replaying an earlier state, inventing approval IDs or rewriting trusted inputs can defeat any pure reducer; durable authenticated anti-replay storage is an external prerequisite, not implemented here. A Decision dataclass can be constructed by Python callers; consumers must call actual reducer and use its returned result, never accept a standalone forged boolean receipt. The target-camera harness integrates separate controllers via this API. Full camera/session/original-settings/owned-cleanup verification remains the controller's obligation, not covered by this per-hop model.

## Tests and execution limits

`PYTHONDONTWRITEBYTECODE=1 python3 [-O] -m unittest -v` in this directory:14 tests PASS normal/-O. Fake-only cases: all individual required observations omitted; every binding field changed; every fault; PID reuse/task/source/executable/socket/namespace/server/transport/device changes; held/pidfd/peercred insufficiency; native clock gaps/staleness/domain mismatch; provenance/reorder/replay; unknown/denied incidents; exact request authority; stale/forged route; terminal failures unhealed by snapshots; pending/repeated op/evidence; same/unknown/new boot and incomplete return; reboot ACK not proof; independent camera; malformed types and disabled old adapter.

No actual Linux syscall semantics, physical authentication, continuous holders, timing bound, remote cancellation, reboot/watchdog success or recovery outcome is established by these tests. Not all OS lifecycle cases are simulated. Source freeze binds only this new module/tests/document; review remains separate from runtime qualification.
