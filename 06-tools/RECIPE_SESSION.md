# Сессионный applier `0x8e` (Lenovo XT2611-1)

Восстанавливает [проверенный трёхзаписный рецепт](../artifacts/ddic_round18_20_recipe_20261119/result.md)
после пробуждения. Не пишет яркость, автояркость, герцовку или Android-настройки.
Не устанавливает модуль KernelSU, boot hook или автозапуск. После ребута
процесс не запущен; оставшийся файл сам ничего не применяет.

## Запуск

Только на XT2611-1 / `W3WWS36.65-64-4-1` с проверенным `msm_drm.ko` и
BOE ILI97701A `cmd_v4` (`0xd2`). Штатный **Flicker prevention** должен быть
выключен и оставаться выключенным во время сессии. Не запускайте параллельно
другие DDIC-инструменты, включая `recipe_bug_hunt.sh`.

После [проверки ADB и идентификации устройств](../03-investigation/adb-remote.md)
выберите транспорт Lenovo (`ADB_T`) и выполните из корня репозитория:

```sh
# Первая установка. Если каталог уже есть, сначала остановите старую сессию;
# команда ниже намеренно не перезаписывает существующую установку.
adb -t "${ADB_T:?}" shell -T "su -c 'umask 077; d=/data/adb/legion-dc-session; mkdir -m 700 \"\$d\" && cat > \"\$d/recipe_session.sh\" && chmod 700 \"\$d/recipe_session.sh\"'" \
  < 06-tools/recipe_session.sh
adb -t "$ADB_T" shell "su -c '/data/adb/legion-dc-session/recipe_session.sh start'"
adb -t "$ADB_T" shell "su -c '/data/adb/legion-dc-session/recipe_session.sh status'"
```

Первое применение ждёт **нового пробуждения**: один раз выключите и включите
экран. Applier требует штатные значения после пробуждения и не принимает
уже выставленный `0x8e` за свой профиль. `running` + `active: verified wake=…`
означает, что последнее применение прошло регистровую проверку. Процесс остаётся на телефоне после отключения
ADB. Он опрашивает поколение пробуждения раз в секунду, ждёт стабильного
`ON` и не пишет в панель при выключенном экране или AOD. Обычно требуется
несколько секунд после пробуждения; до применения возможен штатный PWM.
Опрос не устанавливает wakelock. `waiting-for-next-wake` при старте ожидаем,
`inactive` + `error:` означает, что работа остановилась.

## Остановка / откат

При включённом экране:

```sh
adb -t "$ADB_T" shell "su -c '/data/adb/legion-dc-session/recipe_session.sh stop'"
```

`stopped: stock registers verified` — фоновый процесс остановлен, штатные
байты `0x0e/0x0e/0x50` прочитаны обратно. `stop` пишет их только если этот
процесс сам применил рецепт в том же пробуждении и экран готов. Иначе он
только отключает автоматическое применение; штатная переинициализация панели
при следующем пробуждении обычно сбрасывает рецепт. Не убивайте процесс
вручную в середине DDIC-транзакции. При ошибке прочитайте `status` и `log` в
каталоге applier; не запускайте его повторно вслепую.

Выбор страниц, три записи и возврат на страницу 0 отправляются одним списком
DSI-команд при применении и при откате. На проверенном `msm_drm.ko` драйвер
держит `panel_lock` на весь список: штатный modeset не может сменить страницу
между выбором и записью. Проверяются нативный статус списка и readback всех
трёх регистров. Чтения остаются отдельными операциями: их неудача может
остановить сессию, но не отправляет запись данных на другую страницу.
На закреплённом ELF захват блокировки списка находится в
`dsi_display_cmd_transfer` (`.text+0x1a1984`), а захват той же блокировки
при смене режима — в `dsi_panel_switch` (`.text+0x1c33a8`).

Проверяемый возврат ESD в `reg_read` выполняется отдельно от процесса DSI и
вне его таймаута. При неудаче групповой передачи или при таймауте скрипт
останавливается без повторной записи и без попытки вслепую сменить страницу.
Список защищён от вклинивания modeset, но не гарантирует откат уже отправленных
команд при частичной ошибке транспорта. Не запускайте скрипт повторно при
неопределённом состоянии панели; сначала восстановите штатное состояние.
Это регистровое восстановление,
не доказательство отсутствия мерцания или достижения ≥2 кГц. Срабатывание
на изменение штатного переключателя во время уже включённого экрана не
входит в эту сессию; оставляйте переключатель выключенным.

## Блокировка штатного переключателя — пока не установлена

На проверенной прошивке `DisplayDCMode` из `CoreSettingsExt` реализует
`ProviderSwitch`, но не `DynamicLifecycle`: штатного сессионного входа для
серой неактивной строки у этого пункта не найдено. Бит
`config_moto_display_dc_supported` управляет поддержкой функции, а не
сессионной блокировкой пункта.

В точном GLOBAL `SettingsMoto` (`classes2.dex`, статическая проверка)
`DynamicDashboardTileController.onAvailabilityStatusChanged(5)` оставляет
пункт видимым, но отключает его. Кандидат для интеграции — связать доступность
`display_dc_mode` с той же сессией applier и запретить изменение в её
UI-обработчике, даже если экран настроек ещё не обновил состояние. При `stop`,
ошибке или ребуте штатная доступность должна восстановиться. Пока UI не
изменён; не считать `stock_off`-гейт блокировкой нажатия.
