# Offline snapshot semantic spike

Status: **bounded offline feasibility only**, not integrated/device-ready. This directory adds no controller, child launcher, acquisition, transport, owner action, or next-child authorization. Unknown P85=14 stays disabled; real OLED PWM >=2000 Hz remains unproved. Existing 37/45/8 and short60/overall600 constraints are untouched.

## Two deliberately separate predicates

* STATE_ONLY checks supplied FIELDS, DISPLAY, BOOT, OWNER snapshot content at dbv=3600 against p85_batched_envelope.validate_state. Quiet/state/hold-end envelopes genuinely contain no ESD section. This API neither consumes nor reports ESD. An ESD-looking line in a display dump is irrelevant, not evidence. Child contexts must still use their separately acquired ESD=reg_read and existing complete child receipt predicates. This is not proof of successful ownership acquisition: empty OWNER output plus a caller-supplied zero status is only supplied snapshot content.
* GUARD_TIMING checks supplied PRE_GUARD bytes. The source is run_p85_timed_stock_trial.write_stage: fullmatch "GUARD_TIMING ([0-9]+\.[0-9]+) ([0-9]+\.[0-9]+)\n", float conversion and 0 <= end-start <= 8. The current guard producer prints uptime decimals around its guard command. This port authenticates none of that command, root/panel/owner/boot state, or execution. It does not prove freshness, the 37-second absolute clock, host elapsed time, sensor time, or kernel printk time.

Existing first-spike state.awk and runtime sources were not modified. STATE_ONLY is a separately named adapter, not an optional-ESD weakening of that full predicate.

## File interface

Invoke sh validate_snapshot.sh KIND EXPECTED_BOOT NEW_STAGE followed by one OUT ERR RC triple for GUARD_TIMING, or four triples in FIELDS DISPLAY BOOT OWNER order for STATE_ONLY. GUARD_TIMING uses "-" for EXPECTED_BOOT. Every RC must be exactly "0"; every ERR must be an existing empty regular non-symlink file. OUT/ERR/STAGE paths must be absolute. Stage must not exist. All arguments are validated before record processing. Success means zero exit, empty stdout/stderr, and successful exact owned-stage cleanup; failure is nonzero. There is no success receipt suitable for child admission.

Caller must own a private stable input parent and stage parent, ensure immutable files while validating, and trust PATH, tools, script location, metadata and status provenance. These checks do not establish file ownership, hardlink safety, immutable staging, acquisition success, or same-UID race resistance. Existing files must not be attacker-replaced between checks. No evidence enters shell variables; only paths, counts, and tool diagnostics do. Copies are byte checked before AWK. Evidence caps are 1024/4194304/128/0 for state files and 128 for guard. ASCII printable plus TAB/LF only, with exact LF-terminated records (empty OWNER allowed). Each wc/tr/cmp/awk step checks return status and diagnostic output separately; no pipelines mask status. The stage mkdir and cleanup commands are checked too. Diagnostic substitutions append a sentinel and preserve the producer status, so even newline-only diagnostics cannot disappear. LIMIT: bootstrap mkdir and final cleanup rm/rmdir diagnostic capture is explicitly limited to ordinary NUL-free text from trusted host utilities. Shell variables cannot preserve NUL bytes; this is NOT a byte-exact utility-diagnostic guarantee. Supplied producer ERR files and intermediate file-backed utility diagnostics remain byte-exact: any byte rejects. A NUL-safe bootstrap/final-cleanup design is still required before any stronger general, Android, or integration claim. Cleanup removes only the fixed names in the exact stage created by this call; it never recursively deletes or glob-cleans. A real cleanup failure may leave an owned stage requiring quarantine; it cannot produce success.

## Explicit narrower dialect

This is not universal Python-equivalence:
* State FIELDS must be exactly four unpadded LF lines; BOOT exactly one unpadded LF line. Python strips boundary whitespace. Trusted boot metadata is a nonempty 36-character lowercase hexadecimal/hyphen string. OWNER must have zero bytes.
* Exactly one display line contains mActiveSfDisplayMode=. That line must contain exactly one active-mode token and one later peakRefreshRate= token. Other dump lines are accounted for as opaque display context; they cannot prove currency or freshness. Duplicate/stale active lines reject. The numeric token must end at line end or before space/comma/right brace/right parenthesis. Python's greedy regexp accepts some duplicate-token and junk-suffix cases that this port rejects.
* Accepted numbers are canonical unsigned fixed decimals, integer "0" or no leading zero, 1–9 integer digits and 1–9 fractional digits. No exponent, sign, NaN/Inf, overflow, malformed dot, or higher precision. Python accepts some leading-zero or higher-precision strings; this explicit bounded dialect rejects them.
* Within that dialect AWK uses host binary floating-point subtraction and the same bounds as Python. Tests include both sides of 0/8 and software-refresh threshold boundaries. Host evidence does not establish every AWK implementation's conversion behavior or Android portability.
* Direct snapshot.awk is an internal fragment, not a byte/status-safe API. Only the shell wrapper supplies its prerequisites. BEGIN rejects invalid kind/count/boot before consuming records; occurrence counting rejects an empty token.

## Verification

Run python3 -B test_snapshot.py for public synthetic fixtures and python3 -B test_snapshot.py --private for the narrowly specified three saved runs. Repeat with -O. No bare assert is used. The guard oracle compiles only the exact four AST statements for timing from the current frozen runner, never imports or executes the runner. State oracle calls the exact current validate_state.

Private fixtures are parsed with trusted original manifest nonce/plan and completed public run report metadata. Expected boot comes once from each original initial state fixture, before any mutation. Initial state snapshots can have a non-3600 brightness and are correctly rejected by this fixed-3600 predicate; no malformed mutation supplies trusted boot/plan metadata. Raw snapshots, complete dumps, identifiers and tokens are never printed or copied to Git. Synthetic tests run without private fixtures. Fresh test directories are atomic /tmp/pwm-snapshot-test-* mode0700 and files mode0600; only the exact owned instance is cleaned.

Every accepted synthetic/private mutation is checked against the Python oracle, not just selected rejection expectations. Tests cover fields/count/order, whitespace, duplicated tokens/lines, absent/fake ESD, wrong boot/owner, numeric thresholds/precision, guard bounds/grammar, malformed/nonfinite/overflow cases, extra/control bytes, producer failures/stderr, tool output followed by nonzero status or stderr, and cleanup fault propagation. Tool-fault rows are labeled separately from semantic oracle comparisons.

results-final.json and results-final-optimized.json contain only sanitized counts. frozen-source-blobs.json identifies this deliverable; runtime-source-blobs.json verifies the 13 qualified source files against source1785d32. These are finite-corpus results, not universal subset proof or successful live guard/ownership acquisition.
