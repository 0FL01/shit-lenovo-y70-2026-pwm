# Измерение по изображению осциллографа

`scope_pwm.py` разбирает один кадр **осциллограммы фотодатчика**. Время задано горизонтальной развёрткой прибора, а не FPS снимающей камеры. Полосы на фотографии самой OLED-панели и экранные записи Android **не подходят**. Инструмент не подключается к устройствам. Результат для реальной панели: `unknown`; ниже лишь проверка метода на синтетическом сигнале.

## Как снять отсчёт

1. Сохраните исходный кадр, видимые time/div и V/div, режим пробника, частоту дискретизации прибора, полосу тракта, режим coupling и сведения о фотодатчике. Предпочтительнее экспорт исходных samples, если доступен. Не применяйте фильтры, persistence или усреднение. У камеры снимайте фронтально, без перспективы; наклонённую/искажённую сетку сначала выпрямите и **заново** откалибруйте по нескольким делениям в обоих направлениях.
2. На том же изображении измерьте пиксели/деление отдельно по X и Y. Передайте секунды и вольты на деление с учётом фактического коэффициента пробника. ROI = `left top right bottom`, нумерация от левого верхнего угла, правый и нижний края не включены. Выберите участок только с одной непрерывной цветной кривой; подписи, курсоры, наложенные каналы и сетку того же цвета исключите. RGB и tolerance выделяют цвет линии (максимальная разница каждого канала). Пропавшие сегменты не дорисовываются.
3. Для оптического duty укажите знак изменения напряжения при увеличении света. Для percent modulation дополнительно снимите уровень темнового сигнала при тех же gain/offset, в пикселях исходного изображения. Это **не обязательно** маркер 0 V и не нижняя часть импульса. `--linear-dc-unclipped` означает, что вы независимо проверили линейность, DC coupling, полосу для измеряемой формы и отсутствие насыщения. Не ставьте флаг по внешнему виду графика. Фоновая засветка меняет глубину; фиксируйте условия.

Пример запуска из этого каталога с Python ≥3.11 и зависимостями из корневого `requirements.txt`:

```sh
# Воспроизводимый искусственный кадр; числа ниже относятся ТОЛЬКО к нему:
python -c 'from test_scope_pwm import draw, square; draw(square).save("/tmp/synthetic-scope.png")'
python scope_pwm.py /tmp/synthetic-scope.png --roi 10 5 370 96 --rgb 240 210 45 \
  --seconds-per-div .0005 --x-px-per-div 40 --volts-per-div .2 --y-px-per-div 20 \
  --polarity positive --dark-y 90 --linear-dc-unclipped
python -m unittest discover -s . -p 'test_scope_pwm.py' -v
```

Ожидается **2000 Hz**, duty **25%**, размах **0.4 V**, уровень относительно темноты **0.2–0.6 V**, глубина **50%**. Для собственного изображения подставьте реальные координаты, цвет и масштабы. Без темнового уровня, известной полярности или подтверждённого DC-тракта поле глубины будет `null`.

## Что означают результаты

- `frequency_hz` — **частота следования одноимённых фронтов**, а не основная частота сигнала. Она равна `1 / (median_edge_spacing_px × seconds_per_div / x_px_per_div)`. При чередовании длинного и короткого импульсов каждые 0.5 мс фронты следуют с частотой 2000 Гц, но пара повторяется с частотой 1000 Гц. `waveform_fundamental_hz` намеренно не определяется; `cycle_variation_detected` отмечает заметные изменения ширины или уровня, но не доказывает тождество циклов при значении false. Порог фронта 50%, гистерезис 30/70%; нужны ≥3 полных интервала, ≥12 px/интервал, разброс от медианы ≤max(2 px, 10%), вертикальный размах ≥6 px. Хвост длиной ≥1 медианного интервала без одноимённого фронта в начале или конце ROI считается возможной пачкой импульсов: общая частота не выдаётся.
- `raster_upper_duty_pct` — доля времени в верхнем по напряжению уровне по 50%-порогу. Требуются стабильная ширина (разброс duty ≤max(5 процентных пунктов, 2 px/период × 100)), обе фазы ≥3 px и две выраженные полки в каждом цикле. `optical_high_duty_pct` учитывает, какой уровень соответствует свету. Он выдаётся только при известной полярности **и** подтверждённом линейном DC-тракте без насыщения с достаточной полосой. У синусоиды можно оценить интервал между фронтами, но не выдаётся «PWM 50%». Ограничитель может превратить синусоиду в прямоугольник на картинке; растровый duty не доказывает оптический.
- `trace_vpp_p02_p98`: устойчивый к одиночным пикселям размах, (P98−P02) × V/px. Это оценка по разрешённым уровням, не физический максимум между отсчётами. `dark_referenced_{min,max}_v` используют те же квантили после вычитания темнового уровня и учёта полярности; они не являются абсолютной яркостью. `percent_modulation = 100 × (max−min)/(max+min)`. Если хотя бы один оцифрованный отсчёт ниже dark либо за пределами интервала P02…P98 есть выброс больше max(1 px, 5% размаха), глубина не выдаётся. Более мелкие пики могут быть сглажены или пропущены; изучите исходные отсчёты.
- Код 0 и `confidence=conditional_on_calibration` означают, что растр прошёл геометрические проверки; это не статистическая вероятность, сертификат калибровки или доказательство отсутствия медленной огибающей. Поля `complete_periods`, `period_px_range` и `warnings` нужны для аудита. Если форма/полярность/опорный уровень не позволяют получить отдельную метрику, она равна `null`. Неразрешимая частота/невалидная трасса дают код 2, `status=unresolved` и причину.
- Проверьте измерение при другой развёртке и частоте дискретизации **самого осциллографа**, без изменения состояния дисплея. Не считайте горизонтальные пиксели физическими ADC-отсчётами. Усечённая полоса, aliasing, скрытый более быстрый carrier, потеря узких импульсов, ошибочный dark, аппаратный clipping и оптическая нелинейность не исключаются одной картинкой. Для медленной огибающей нужен отдельно длинный захват. При спорном результате не используйте его как доказательство достижения порога 2000 Hz.

Для наложенных и пересвеченных стендовых трасс, где выделение одной кривой неприменимо, использовали другой метод: [D/L для сравнения фотографий](../../artifacts/scope_divergence_20261118/result.md). Пример применения и границы вывода: [пространственное чередование и DC × DBV](../../artifacts/scope_spatial_stock_20261118/result.md). Это описание изменения рисунка, не измерение оптической частоты.
