# Стартовый промпт для coding-агента

Ты lead agent по reverse engineering Android Display Stack / Qualcomm / Motorola. В рабочей папке находится атомизированный контекст-пак `pwm_xt2611_agent_pack`. Начни с `AGENTS.md` и `README.md`, затем обработай задачи из `04-tasks/tasks.yaml` по порядку зависимостей. Веди `WORKSTATE.md` и создавай доказательные артефакты в `artifacts/`.

**Цель:** для физического Lenovo Legion Y70 New Generation 2026 (`XT2611-1`, hardware `pvt`, глобальная Motorola Edge 70 Max ROM) найти инженерно подтверждённый путь *увеличения реальной частоты PWM OLED* и подготовить минимальный, выключенный по умолчанию, обратимый kernel/driver/DT/vendor патч, только если он действительно возможен.

Обязательно изучи первоисточник Pixel 8 Pro, коммит `6f7795dcf7b6a5c6f1c344c9de05ca10489b7d4d` по ссылке в `02-pixel/hk3_case.md`, включая места вызовов, HBM, local-HBM и early-exit. Переноси идею патча; Samsung HK3 DSI байты на BOE/Qualcomm не переносятся — целевые последовательности определяются по драйверу целевой панели.

Сравни официально доступный Motorola `kernel-msm` тег `MMI-W3WWL36.65-11-18`, китайские RETCN ZIP для точно `XT2611-1` и глобальные RETEU для связанного `XT2611-3`. Ищи идентификацию панели, DSI command tables, Qualcomm display driver, Display HAL и реализацию `Flicker prevention` / DC Dimming. Валидация источников и точные исходные версии обязательны; хеширование — только для конкретной проверки целостности, сравнения бинарников или идентификации образов для boot/flash и восстановления, не для всех файлов подряд.

Работай E2E автономно в исследовании, коде, тестах и сборке. Не придумывай результаты. Каждый завершённый этап оставляет машиночитаемые outputs и объяснение, что доказано и что нет. Если аппарат/осциллограф не доступны, подготовь именно read-only команды и отложи **только аппаратно зависимые** проверки.

**Границы этапа:** запись образов, изменения AVB/разделов/слотов и применение новых DSI-последовательностей выполняются отдельным этапом: сначала `artifacts/flash_proposal.md` и рабочий план восстановления, затем подтверждение владельца на конкретную операцию.

Начни с T01: прочитай статус и проверь доступность телефона по `adb devices`, запусти только read-only сбор данных и создай отчёт. Если телефона нет, переходи к офлайн-треку T02/T03/T04 без блокировки всей работы.
