# R12b: слепой пространственный декодер, все 18 кадров

**Итог: обязательный pixel gate не пройден.** На всех 15 кодовых кадрах удалось распознать не менее 62/64 клеток (12×64, 3×62; суммарно 954/960, не 960 независимых опытов). Все 6 пар инверсий прошли (63–64/64, медиана знаковой разности 58,29–62,14 уровня превью). Три кадра равномерной плашки не дали ложного распознавания: макс. |NCC| по двум семействам 0,056 / 0,062 / 0,172, межклассовое разделение по рангу 5,01 / 3,96 / 9,30 (<12). Это подтверждает различимость этих пространственных рисунков в этой серии, но не пригодность каждого снимка короткой экспозиции.

У шести кодовых кадров минимальный внутристрочный разрыв между четвёртой и пятой клетками ниже заранее зафиксированных 12 DN: p01_1 0,64; p01_3 1,27; p03_1 0,89; p03_3 1,87; p06_1 0,72; p06_3 3,31. Два из них также нарушили проверку цифровых крайних значений RGB: 1 и 9 из 1280 целочисленных пикселей в центральных частях клеток. Это не измерение клиппинга сенсора. Полные покадровые критерии выполнены у **9/15 кодовых** и отдельно **3/3 отрицательных**. Не выбираем лучшие кадры, не усредняем серию для превращения fail в pass. Старый абсолютный порог R10 дан в каждой записи отдельно (58–64/64); R11 short2 остаётся fail. Свидетельство состояния камеры, источника и геометрии публикуется отдельно и не отменяет этого отказа.

**Повторяемость:** по фазам 1,4826×медиана абсолютных отклонений от медианы трёх кадров каждой клетки составила 0,98–2,27 DN. Однако максимальные отклонения достигали 68,01 DN; даже у однородного контроля максимум 22,40. Низкая медиана не исключает локальные провалы. Это статистика обработанного превью, не шум сенсора. Физическая причина локальных потерь не установлена. Только два независимых кодовых семейства, одно положение камеры; никаких p-value, экстраполяции на все панели, цвет, измерения яркости, PWM, герц или построчной шкалы времени.

## Запечатанная последовательность

1. До опыта: `original_freeze.sha256` — идентичная исходная таблица хешей SPEC, генератора, декодера и scorer; её SHA-256 `5285639f7dccff76abab209a2c5280d5c4c42a1a6c8aabde2225a3098c88b35f`. Для нового запуска R12b оператор подтвердил SHA-256 частного salted key `6684bf87f9ef6de8c6d33a9b6118aabb988d6926facf4accd7616f2ea176d747`.
2. Декодер получил только 18 отдельных PNG с метками p01_1…p06_3, без исходных страниц, кода, ключа или имён фаз. Хеш полного файла **предсказаний до открытия ключа**: `c3c353e34585c4e4b4bc60d16586d813219bc1372a9a2714f23f09e3b1a56079`. Он передан оператору до раскрытия. Отказ сети при одном вызове не изменил входов, оценивания или числа кадров.
3. Уже после фиксации предсказаний оператор открыл ключ, scorer проверил оба хеша. Порядок: −D,C,D,−C,U,C. `outcome.json` — неизменённый полный результат scorer, SHA-256 `e634b72e37f8361c80b31c9c3d052631de61997011f33eeed03214e8fe8a2364`. `preview_aggregates.json` сохраняет все поля, используемые scorer: хеши изображений, старые решения и новые ранги, 64 клеточных медианы Y, статистику границ размаха/ряды. Публичная копия исключает неиспользуемые RGB-медианы. `revealed_codes.json` содержит раскрытые маски и порядок, **без соли**: эти две публикуемые копии не должны иметь хеши первоначальных закрытых файлов. Снимки, читаемые детали помещения и значения присоединения не публикуются.

## Воспроизведение

`python3 -P test_public_replay.py -v` пересчитывает полный score из опубликованных агрегатов; `python3 -P test_synthetic.py -v` делает 18 искусственных PNG и проверяет обработку, отрицательные примеры и отказ при повторной записи. Нужны NumPy и Pillow. `score.py` и `SPEC.txt` совпадают с первоначальными байт-в-байт; `operator_plan.py` — тот же операторский генератор, переименованный, чтобы не затенять стандартный модуль Python operator. Код `predict.py` отличается только способом нахождения прежней геометрии (теперь путь относительно репозитория; сам JSON защищён тем же SHA-256), а не пиксельным методом. Повторный прогон этой копии на исходных закрытых 18 PNG дал тот же SHA закрытых предсказаний. Не добавляйте в каталог входов ничего кроме 18 кадров. Для проверки цвета нужен отдельный опыт, см. `future_color_protocol.md`.
