# Уже существующий refresh-sweep: использовать перед новой съёмкой

**Сопоставимая серия есть:** один непрерывный ролик Pacman,
**120 → 144 → 120 → 90 → 120**, DC0/native DBV3600, 100 мкс/ISO6400,
фиксированные focus/crop/skew/zoom, AE/AF/OIS/EIS OFF. Это одна камера и
геометрия внутри серии; камера не нынешняя A001. Нельзя смешивать её
~93-строчные периоды с ~50.6 строками новых A001 роликов как измеренные Hz.

## Источники

- [run.json](run.json): пять контролируемых фаз, одинаковый DBV, настройки
  камеры в начале/конце каждой выдержки, software mode и чистый возврат.
- [analysis.json](analysis.json), [result.md](result.md): сохранённая проверка
  всех 62 native timing packets по live DT, десяти одинаковых DBV writes,
  PPS, отсутствия writes в hold и 85 неотрицательных controller returns.
  Переход к 90 проходил через idle timing@7, затем timing@2; это учтено.
  Сырые исторические kernel logs отсутствуют в текущей серверной копии,
  поэтому эта native-квалификация здесь не воспроизводилась заново.
- [Оригинальный ролик](../optical/pacman_stock_base_rates_20261107.mp4):
  существует, размер 110159667 байт совпадает с журналом; HEVC 1280×720,
  limited-range Y, 2845 кадров. Rotation metadata отсутствует.
- [temporal_alias.json](temporal_alias.json), [temporal_alias.py](temporal_alias.py):
  уже сохранённая complex-phase диагностика, не измерение физических Hz.

## Повторная проверка из оригинального видео

2026-11-08, только offline. Native Y декодирован с `-noautorotate`,
`extractplanes=y`, без изменения диапазона. ROI [540,190,60,500]. Пять старых
центральных 75-кадровых окон заново дали те же mean Y и fine-пики. Все прежние
temporal aliases также воспроизведены из исходного видео.

Дополнительно q **зафиксирован на первом stock-контроле**:
0.010706583658854168 cycles/row для всех пяти фаз. Least-squares модель:
квадратичный spatial trend, broad nuisance q/6, spatial harmonics 1–4;
unwrapped phase основного complex coefficient fitted against original MP4 PTS.
Отдельный detrend2/Hann projection на том же фиксированном q даёт тот же класс
~1.3 cycles/s, включая 144. Это исключает зависимость результата только от
перестановки q вслед за пространственным пиком.

Минимальная амплитуда fitted основного коэффициента при 144 — 2.55 Y-кода,
phase residual RMS 0.0333 cycle: это не фаза исчезнувшего шумового компонента.
PTS intervals 33.233–33.433 мс. По отдельным camera frameCount/timestamp
снимкам cadence 30.000373–30.000378 fps, но они не являются покадровой
привязкой sensor exposure к MP4. Software refresh также не калибрует
физический panel clock. Остатки fit не являются physical-Hz error bars.

## Что уже проверено и чего не обещать

- Простая пространственная пропорция q ∝ refresh не наблюдается: 144 меняет
  fine q примерно на 7%, а не 20%;90 остаётся рядом с 120. Собственная OLED
  развёртка и camera scan могут менять q, поэтому это не прямой temporal counter.
- Упрощённая гипотеза **шесть импульсов на кадр** дала бы при camera ≈30 fps
  иной alias на 144 (иллюстративно 864 Hz → −6 Hz), которого в сохранённом 144
  видео нет. Это свидетельство против этой конкретной модели при её
  допущениях, не доказательство фиксированного 720 Hz carrier.
- Для произвольного integer N и идеальных номинальных частот 90↔120 меняет
  частоту на 30N, невидимые при 30 fps; 144↔120 даёт 24N mod30. Если N кратно 5,
  все три режима могут сохранить один alias даже при меняющемся carrier.
  Harmonic order и реальные clocks дополнительно неизвестны.

**Рекомендация:** не повторять аппаратную последовательность только ради
вопроса, уже покрытого этим видео. Новая A001-серия с одновременными C1 и
актуальными native anchors была бы новой привязкой текущего состояния, но
сама по себе не различит все fixed-count/fixed-carrier модели и не докажет
≥2000 Hz. Для этого нужна заранее сформулированная дополнительная проверка,
а не обещание снять неоднозначность повтором тех же commensurate rates.
Новые device-команды и изменения существующих результатов не выполнялись.
