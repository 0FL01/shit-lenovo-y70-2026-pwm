# Эталон Nothing: новая офлайн-проверка фото и видео

2026-11-07. Экран Nothing с2160Hz принят по прямому подтверждению владельца
(`reported`). Ниже — измерения **изображений**, не новое независимое измерение
2160Hz и не достигнутые≥2000Hz на Lenovo. Профиль Lenovo не изменялся.

и можно ли переносить на фотографию временную базу камеры из предыдущего preview?

## Выполненный эксперимент

Переиспользован `06-tools/optical_spectrum.py`: пространственный quadratic trend
и Hann, **без вычитания временного среднего**, с сохранением total/coherent/
incoherent. Анализ6 узких вертикальных колонок фото и5 колонок видео: в каждой
видео-колонке105 кадров и три неперекрывающихся подокна по35. Узкие колонки
не усредняют весь наклонный рисунок по ширине. Фото — RGB-weighted code values;
видео — исходный Y plane без преобразования диапазона. Их амплитуды **не сравниваем**.

| Наблюдение | Результат |
|---|---|
| Основной пространственный период фото |58.935–59.796px|
| Основной период видео, все20 окон |18.450–18.789px|
| Отношение медианных периодов фото/видео |3.188406|
| Отношение ширины4096/1280 |3.2|
| Отношение двух масштабов |0.996377 (разница около0.36%)|

Во всех26 спектрах главный пик внутренний, не граница поискового диапазона.
Видны пространственные кратные компоненты примерноP/2 и местамиP/3. Не называем
их независимыми PWM-режимами. Интервалы выше — разбросROI/окон, **не доверительный
интервал**; точки сцен не совмещены, zero-padding не улучшает физическое разрешение.

В четырёх исходных видеокадрах local phase fit наROIx700/y260/w400/h250 даёт
`qy=0.05371094 cycles/px`, `qx≈−0.014585…−0.013835`, наклон полос
`dy/dx≈0.258…0.272`; остаток фазы около0.0038–0.0054цикла.
Это реально наклонный fine-train. Его межкадровое движение не переводим вHz.

**Подтверждённый промежуточный результат:** получен сохранённый фото/видео
оптический образец экрана-эталона; пространственный масштаб fine-train согласуется
между двумя выходными разрешениями камеры. Это baseline измерительного метода,
не улучшение Lenovo-панели и не замена сохранённого A9-only baseline.

## Временная база: полезное расхождение, не фиктивная калибровка

Если *предположить*, что именно этот fine-train — компонента2160Hz, время сенсора
идёт вдольy, а строки OLED почти вертикальны и нет ISPwarp, период фото требует
приблизительно **7.74–7.86µs/output-row**, то есть **23.78472–24.13194ms** на3072строки
(first→last+1). Считать эти3072 output rows всейactiveArray — дополнительное
непроверенное допущение, а не установленный факт покрытия сенсора.
Отдельный setup-preview сообщал `rollingShutterSkew=27.011343ms`.
Разница порядка11–12% не исчезает от округления FFT.

Это не опровержение принятого эталона2160Hz. Не проверены: режим сенсора именно
при фото/владельческом ролике, output-to-sensor time map, локальная геометрия строк,
номер физической гармоники. ВыборомROI/знака нельзя подгонять их под нужныеHz.
**Простой перенос preview skew на этот JPEG не обоснован.**

Первичный контракт Camera2 уточнён по AOSP `android16-release`,
[`system/media/camera/docs/metadata_definitions.xml`](https://android.googlesource.com/platform/system/media/+/refs/heads/android16-release/camera/docs/metadata_definitions.xml):
`sensor.rollingShutterSkew` относится кfirst→(last+1)row всей`activeArraySize`;
при crop/binnning требуется масштабN/H используемых sensor rows. Делить27ms
на720 без crop mapping неверно. Документированная семантика не доказывает
её точную реализацию vendorHAL и не восстанавливает отсутствующие capture results.

## Проверки и воспроизводимость

`analyze_reference.py` использует только локальные входы, NumPy/Pillow/ffmpeg и
существующий spectral helper. Полный decode165frames согласован сPTS/nb_frames,
timestamps строго возрастают, outputs не перезаписываются. Проверено тождество
total=coherent+incoherent. Synthetic phase-gradient на трёх неподвижных фазах
восстановил известныйqx с ошибкой<1e−10;10 ближайших unittest спектрального
анализатора иsyntax check прошли.

Независимое ревью воспроизвело6+20 профилей и4 phase fits точно; блокирующих
замечаний нет. Исправлена first-to-last конвенция3071→3072 для сравнения с
Camera2 first-to-last+1; это0.033%, не объяснение основного расхождения. После
исправления полный расчёт повторён в отдельный private output и сопоставлен
сJSON. Полнота покрытияactiveArray по-прежнему не доказана.

## Следствие для следующего шага

Нельзя сопоставлять59px фото Nothing с93px прежнего720p видео Lenovo напрямую:
различаются камера, разрешение, временная база и геометрия. Новый эталон полезен
для подготовки контролируемой оптической серии; **из него не получен профиль
Lenovo≥2000Hz**. Следующий уже подготовленный причинный аппаратный тест остаётся
`../dsi_coupled_9d_20261107/proposal.md`: отдельная точная авторизация отсутствует.
Этот анализ её не создаёт и не повторяет израсходованные S0C1/A9 эксперименты.
