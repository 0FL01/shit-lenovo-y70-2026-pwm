# Inactive identity-bound raising reader revision

## Implemented interface

reader.py contains real dependency-injected functions, not evidence booleans: Acquisition.acquire(pid, deadline) returns a Held handle; Held.read_stat(deadline) returns validated raw stat bytes or raises; Held.close() closes only acquired descriptors. All OS/poll/clock dependencies are explicit. No imports trigger proc, child, socket, signal or host actions.

RootPin contains an externally approved borrowed proc-root FD and expected dev/inode/mode, PID namespace and evidence reference. Structural validation and fresh comparisons are implemented. Authentication of procfs mount, PID-namespace linkage and root-pin provenance is NOT implemented: a correctly shaped hash/reference is not authority. Caller must also own the descriptor namespace without concurrent close/dup/reuse. fstat comparisons detect sampled mismatch but are not an atomic anti-hostile-FD-replacement guarantee.

Acquisition opens the numeric PID directory once relative to that held root, then all stat opens use only fixed relative stat under the held task directory. It obtains a live stat, opens one pidfd, polls nonready, re-reads live stat through the original held directory and compares starttime, namespace and pidfd metadata. This closes the detected acquisition exit/reuse cases under the explicit authenticated-proc/same-PID-namespace assumptions. Equal starttime alone is not kernel-object proof; the held-dir live stat after pidfd acquisition supplies the conditional race bracket. A nonready pidfd alone is insufficient. No new numeric directory lookup occurs after acquisition.

Each read checks root/task descriptor metadata, namespace and pidfd before and after the same relative read. Exit, unknown poll result, malformed data, cap/deadline, namespace ambiguity and all errors make this handle and acquirer terminal. It never retries or resets. On failure owned handle closure is attempted; later reads fail before I/O. This is a new revision's explicit stricter terminal contract, not a claim that the old dependency used identical timeout semantics.

The read loop has16KiB/65-call caps and existing absolute deadline checks. Returned FDs are registered before post-call deadline checks. Owned close is attempted after failures/deadlines and never retried; failure is retained, not treated as definitely closed. Existing ordinary read/finally-close masking is preserved: if both fail, close exception is raised with read exception in context; both stage/errno events are retained. Acquisition/outer handle cleanup preserves the active primary exception. Logging prefix128, dropped count, logging_failed and last_error are bounded best-effort evidence, not proof of absence of earlier failures. No hard OS cancellation or universal cleanup success is claimed.

## Evidence and validation

10 fake tests normal/-O cover actual public OS API signature binding without invocation, successful relative-only reads, acquisition PID/starttime change, exit/zombie, hidepid-like ENOENT, permission denial, namespace mismatch, descriptor reuse, read ENOENT/ESRCH/EACCES/EPERM/EIO identity preservation, read+close masking, exit across read, cap/deadline and terminal no-I/O behavior. These are isolated fake inputs, not live kernel qualification. Stages record type/integer errno only, never error text/args or private paths.

Prior reviewed held_task_observer_20261109_01, raising_reader_hook_20261109_01 and owned-child sample informed this code. None is substituted as a production reader and prior errors remain historically unattributed. [Linux proc documentation](https://docs.kernel.org/filesystems/proc.html#process-specific-subdirectories) distinguishes held proc references from numeric PID reuse. [pidfd_open](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) specifies task lifetime/poll semantics, not executable or socket authentication. [Linux v6.12 proc/base.c](https://github.com/torvalds/linux/blob/v6.12/fs/proc/base.c#L726-L778) demonstrates ENOENT visibility denial and ESRCH task absence; errno alone never becomes a benign exit authorization.

## Integration remains separate

This new reader does not implement the full LinuxProcFS API and cannot be dropped into the current loader or association. A separate reviewed mapping must allocate an independently qualified handle for each required stat task, map source/pin/budget ownership, and propagate every new terminal error into actual ProbeError(trust_invalidated=True)/association sticky failure. The old safe_errors decorator must not silently wrap a new logical BoundError as noninvalidating. Genuine OSError objects/contexts must remain available in the chain. No such production mapping has been applied here. Complete process enumeration still cannot skip a vanished or unreadable task, and each source/dependency revision would enter a new executed-source closure. New mount/root/task evidence does not admit the old invalidated adapter.

Task lifetime, executable identity and accepted-channel/sole-holder custody remain distinct. This code proves no executable immutability, full namespace authentication, nonleader visibility or continuous server FD ownership; server/target/camera recovery and stock remain HOLD.
