# R113. Проверка гипотезы о полосах прямой камеры

**HOLD для физического измерения.** Проверяющий скрипт работает только с уже
подготовленными сводками; он не снимает, не разбирает кадры и не удостоверяет
указанные в JSON допуски. Тесты синтетические. Смысл и выбор выдержек см.
в [протоколе](../night_r109_r112/camera_exposure_bracket.md).

## Не перепутать наблюдаемую величину

Для линейного кадра при постоянном усилении абсолютные цифровые уровни
переменной составляющей растут ещё и пропорционально выдержке. Так даже идеально
сгенерированная компонента 720 Гц дала бы отношения сырой амплитуды
1 / 2,52 / 2,89 вместо ожидаемых отношений 1 / 0,841 / 0,667. Для кода нужна
амплитуда в фиксированной спектральной полосе, делённая на DC после вычитания
чёрного, не мощность, не сырой DN и не диапазон JPEG. Не подставлять ноль вместо
результата ниже шума: подтвердить верхнюю границу и использовать интервал
от нуля до неё. Модуляция одной полосы не является глубиной полного сигнала.

## Ввод и проверка

`python3 -B verify.py измерения.json`. Схема и пример формы ввода в
`test_verify.py:fixture`; это искусственный пример, его числа не задают точность
камеры. `actual_time_us` — одновременные внешние границы фактической выдержки в
микросекундах, `amplitude` — одновременные внешние границы указанной безразмерной
амплитуды. В границы заранее входят шум, дрейф и неопределённость нормировки.
У каждой серии один неизвестный положительный масштаб. Заполнять `gates` только
по отдельной проверке с сохранёнными свидетельствами. Булевы значения не заменяют
привязку кадров, контроль геометрии или линейности.

Скрипт требует минимум два независимых блока каждого порядка
(S→M→L→S, S→L→M→S), доказуемый возврат и разделение фаз. Допуск по частоте
используется для консервативного исключения кандидатов; для положительного
результата дополнительно нужен совместимый набор при номинальной частоте.
Это сознательно может вернуть HOLD даже для физически подходящего режима,
а четыре блока не означают заданного доверительного уровня.

`CONDITIONAL_COMPONENT_MATCH` означает «один из трёх вариантов при данных
допущениях». Это **не** измерение основной частоты: третья гармоника 720 Гц
воспроизводит ответ компоненты 2160 Гц. Более того, на точной сетке 52 мкс
пары f и 1/(52 мкс) − f дают ровно те же нормированные отношения sinc; например
2160 и около 17070,77 Гц. Опция выбора «ближайшего» отсутствует. Этот расчёт
ничего не доказывает о происхождении следа осциллографа.

Воспроизведение: `python3 -B -m unittest discover -v` и
`python3 -OB -m unittest discover -v` из этого каталога (14 синтетических тестов:
9 для `verify.py` и 5 для `dng_qualify.py`).

Для диагностики одиночного нативного DNG 0,6× (`qualify-one`) и сборки
проверяемого JSON-ввода серии (`build-bracket`) предусмотрен
[офлайн-квалификатор DNG](dng_qualify.py). Он проверяет тег фокусного
расстояния на попадание в диапазон 1,35–1,95 мм (отсекает 1×), размеры
`3264×2448`, прямоугольную раскладку `CFALayout`, нулевое верхнее насыщение в
экранном и темновом ROI и отсутствие нулевых отсчётов на экране по умолчанию
(противоречащий измерениям `gates.no_clipping=true` отклоняется), читает две
зелёные фазы Байера раздельно без демозаики и оценивает только две заранее
выбранные пространственные полосы (2160 Гц и ~17 070,77 Гц при шаге строки
13 мкс) с учётом внеэкранного темнового фона. Без независимо обоснованных внешних границ амплитуды `build-bracket` принудительно оставляет
`intervals_cover_noise_and_drift=false` (`HOLD`). Реальные снимки A001 пока
отсутствуют (`HOLD`).
