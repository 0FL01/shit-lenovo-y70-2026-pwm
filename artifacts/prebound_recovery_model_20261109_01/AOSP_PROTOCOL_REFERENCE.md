# Official AOSP smart-socket reference audit

Bounded source-text lookup only. Four official Android repository files were downloaded without compilation/execution and compared byte-for-byte to immutable AOSP reference commit `1cf2f017d312f73b3dc53bda85ef2610e35a80e9`. Local bytes, hashes and exact URLs are in aosp_reference/manifest.json and revision_verification.json. This reference is NOT a source/binary correspondence proof for the independently pinned serving executable. No host/device endpoint was contacted.

## Concrete source findings

- [sockets.cpp784–815](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/sockets.cpp#784) accumulates four-hex-length smart requests and waits for complete data. [961–980](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/sockets.cpp#961) creates a smart socket and enables its peer. These inspected blocks contain no idle lease timer, but that is not proof of unlimited lifetime across the entire server/OS.
- [adb.cpp1294–1354](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/adb.cpp#1294) handles exact serial/id transport selection, assigns the acquired transport and replies OKAY with SwitchedTransport. [sockets.cpp864–868](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/sockets.cpp#864) clears its request buffer and retains the smart socket for a subsequent service. A preselected channel is therefore a concrete supported reference transition, not intrinsically impossible.
- [sockets.cpp911–936](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/sockets.cpp#911) rejects missing/offline transport, then transfers the peer to a remote service and closes the smart-socket dispatcher. Selected service channels cannot be assumed to become arbitrary new smart sockets afterward.
- [services.cpp250–258](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/services.cpp#250) creates a device tracker for track-devices/track-devices-l. [sockets.cpp891–908](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/sockets.cpp#891) replaces the smart dispatcher with the host service.
- [transport.cpp606–693](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/transport.cpp#606) streams length-prefixed device lists and initial/update notifications. Its device_tracker_enqueue at649–653 closes immediately on client data. Sending a later transport/service request on the tracker socket is therefore an explicitly rejected branch. Keep any tracker receive-only and use separate reserve sockets.
- [adb.cpp1479–1481](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/adb.cpp#1479) handles host:version immediately; [sockets.cpp861–863,938–945](https://android.googlesource.com/platform/packages/modules/adb/+/1cf2f017d312f73b3dc53bda85ef2610e35a80e9/sockets.cpp#861) then tears down a handled request. Do not consume a reserve with host:version and assume that same FD remains reusable. Per-reserve server identity must not rely on an invalid repeated-version handshake.

## Refined possible and unsupported branches

Potentially feasible in principle: finite preopened, unconsumed host smart sockets plus an independent receive-only tracker, held against a continuously qualified same-server identity. After a separately authorized incident and positive gate, use distinct reserves for supported one-shot inventory/selection/identity operations; reidentify the exact target and changed boot/root before restoration. A reserved unselected socket need not carry the pre-reboot device transport. This avoids asserting universal verification impossibility from a consumed selected shell channel.

Rejected: repurpose tracker as command channel; reuse a completed host:version socket; accept a new server after exit; reconnect or refill reserves after an uncertain request; infer target boot/root from inventory; treat an open FD as sufficient independent trust; use reserves when incident cause is UNKNOWN or a real denial.

Smallest remaining qualification: bind exact serving build to reviewed behavior or separately establish supported transitions in an explicitly authorized bounded read-only qualification; prove pre-opened connection/process association and finite idle lifetime; test partial-frame/EOF/idle-loss/USB-session changes with no retries; allocate a finite reserve count for complete target+camera verification/restoration requirements; and independently qualify the actual stop/reboot/restoration actions. No real socket or service qualification is authorized or performed here.

The existing fake model does not implement this reserve/tracker protocol. Its twelve passing tests establish only incident classification and one-shot capability gates. Source findings improve feasibility analysis but do not supply a trusted recovery route, resolve01/02 or lift stock HOLD.
