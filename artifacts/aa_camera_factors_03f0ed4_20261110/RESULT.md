## Что эти проверки объясняют и не объясняют

Наблюдение: нет обнаруженной смены перечисленных camera controls, crop, resolution, frame-type mix или явного разрыва PTS. Это ослабляет только соответствующие простые объяснения sham variation.

Hypothesis: при короткой экспозиции 100 us и ISO6400 noise/black-level/ISP processing могут влиять на малые коэффициенты encoded Y; фиксированные AE/AF не фиксируют всю обработку. Rolling-shutter sampling и относительная phase/display-camera cadence могут менять пространственную fine amplitude на конечной высоте ROI, даже без изменения панели. Небольшое движение/defocus или внутренний ресэмплинг остаются возможными. Lossy quantization и межкадровое prediction могут модулировать метрику, несмотря на одинаковые GOP counts. Ни одна из этих причин здесь не идентифицирована.

Unknown: действительные per-frame exposure/gain/readout/crop, линейная яркость, camera modulation transfer, изменение физической панели и вклад каждого механизма. Из одного H264 потока нельзя однозначно разделить изменение оптического источника и measurement pipeline. Заявленный skew не является калибровкой времени на encoded row: нельзя делить его на 720 и переводить q в PWM Hz. q=0.019775390625 cycles/camera row остаётся пространственной характеристикой.

Исходный провал right sham >5% и acquisition rejection сохраняются. Не менять порог/ROI/band, не усреднять ROIs для обхода критерия; нынешняя диагностика не даёт разрешения на AA10/P85-14. Проверка текущих байтов не восстанавливает historical created-inode custody; отсутствие concurrent writers остаётся доверенным допущением.

## Малое следующее наблюдение, только предложение

Offline join уже выполнен (`codec_join.json`, `join_diagnostic.py`): main amplitude/packet-bytes Pearson r baseline/sham/return = 0.124/0.265/0.216; P-only = −0.231/0.688/0.609. I/P mean amplitudes: baseline 0.260309/0.248379; sham 0.254563/0.260256; return 0.250864/0.250456. Везде I n=2, P n=58. Sham повышение сохраняется в P-only сравнении. Это post-hoc описательные величины, без p-values/независимых trial предположений: bytes относятся ко всему кадру, общий тренд/content/noise влияют на обе величины. Не подтверждают causal codec contribution.

Согласованный с temporal audit ближайший prospective шаг: после отдельного scoped execution assignment и проверки применимой авторизации/guards (этот отчёт сам ничего не разрешает) одна bounded steady-stock запись ≤15 s, без DSI/replay/settings writes, без входа в isolation/table transaction и без продления существующего 37 s guard. Если текущий инструмент не поддерживает независимый no-write capture, сначала offline proposal; не запускать full-trial как обход. Воспроизвести исходные brightness/native display state/scene/геометрию и manual100 us, ISO6400, focus2.0387485, zoom1, AE/AF/EIS/OIS OFF; неизвестные brightness/scene значения не угадывать, сверить сохранённый manifest. Experimental DBV3600 отличается от последнего original DBV6438: при таком mismatch no-write observation обязана остановиться; воспроизведение experimental режима требует отдельного explicit setup-mutation proposal, без скрытых brightness/settings/native writes. Текущий assignment только offline; это не blanket requirement нового user approval на любую camera-only запись. После отдельно проверенного stable capture anchor заранее фиксировать четыре 60-frame окна с центрами 2/5/8/11 s. Использовать те же три ROI, q, detrending и full-height Hann; исходный all-ROI5% criterion не менять. Новые окна внутри одной записи не независимые trials.

Abort: дискомфорт владельца, thermal warning, непреднамеренное изменение target/camera state, геометрии/сцены, controls, capture/PTS/acquisition failure. Не исправлять settings автоматически в середине observation и не продолжать ради PASS. Повтор сопоставимой вариации без DSI показывает stock/camera/scene variability даже без операции и оставляет контроль непригодным. Отсутствие вариации не доказывает, что старый drift вызван записью панели, и не даёт candidate admission. Source-bound acquisition validity и все исходные gates обязательны отдельно.

Это минимальный тест повторяемости, не идентификация панели против камеры. Для физического разделения нужен независимый канал: после отдельного scoped execution assignment, проверки применимой авторизации/guards и API capabilities можно сравнить синхронный до-H264 camera-Y с H264 (вариация только H264 поддержит codec contribution; согласованная вариация отвергнет codec-only, но не sensor/ISP). Для отделения панели от camera sampling требуется независимый синхронный оптический наблюдатель/калиброванный reference. Не обещать существование такого потока на основании ImageReader requested=false. Ни одно предложенное наблюдение не выполнено.

## Воспроизведение

`audit.py --private-output <new private cache directory> --summary-output <new summary file>` запускается Python3 с numpy и ffprobe, только на этих сохранённых входах. Он проверяет исходные hashes до/после, требует новый private каталог и не перезаписывает summary. Private probe содержит только allowlisted codec/frame/packet поля. `summary.json` сохраняет первый результат, `verified_summary.json` повторную проверку с явными decoder crop values. Ни одна запись не меняет исходный run/video. Не запускать с изменёнными входами или для кандидатов.
