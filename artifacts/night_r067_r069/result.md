# R067–R069: что архив подтверждает об управлении дисплеем

Три архивных вопроса **DONE**, не три измерения света. База источников `6ba47f4`: XT2611-1 PVT, GLOBAL W3WWS36.65-64-4-1, BOE cmd_v4. Проверка только по файлам Git; приватные журналы, кадры и устройства не открывались. Новых воздействий и съёмок 0, возврат для этих раундов не требуется.

### R067. Совпадает ли сохранённый Flicker prevention с применением?

Критерий: сравнить запрос фазы, возвращённое значение Motorola provider и kernel panelDC; отдельно перечислить **все** полные исходящие DC-наборы по времени внутри каждого окна, а не присвоить один каждому нажатию. [Шесть фаз, поле phases](../stock_dc_trial_20261106.json); [trace: markers, exact_dc_set_matches, native_returns](../stock_dc_trace_analysis_20261106.json); [тракт и смысл panelDC](../driver_callgraph.md#ui--provider--system-server).

| Android / установившийся DBV | Запрос | Provider / panelDC | Полные DC-наборы в интервале маркера |
|---|---|---|---|
| 78 / 5197 | OFF → ON → OFF | 0/0 → 1/1 → 0/0 | [ON, OFF] · [ON] · [OFF] |
| 40 / 2839 | OFF → ON → OFF | 0/0 → 1/1 → 0/0 | [нет] · [ON] · [OFF] |

**confirmed-on-target** по прежней записи: проверены 6/6 плановых фаз одной сессии, шесть полных наборов совпали с выбранным DT по типам и payload, каждый 75 пакетов/875 байт; все 9 наблюдаемых возвратов функции параметра равны 0. Это согласование на уровне software + исходящей передачи, не шесть отдельных независимых экспериментов. Первое ON произошло при пробуждении с ещё включённой подготовительной настройкой до нажатия OFF; повторное OFF при переходе к 40 не сопровождалось полным новым набором. Установка в provider, software-cache, panelDC и исходящая передача не взаимозаменяемы. Само состояние регистров DDIC, задержка UI→свет и оптический исход **unknown**. Дальше различил бы их синхронный, независимо атрибутированный оптический ответ в контролируемом сравнении с sham.

### R068. Extra Dim меняет цифровые каналы или DBV?

Критерий: проверить полные записанные поля до/ON/после; не считать программные ниты, код яркости или фото следа измерением света. [Четыре снимка target_snapshots и EXIF](../STOCK_EXTRA_DIM_20261118_data.json), [результаты второй серии](../stock_extra_dim_locked_20261118/observations.json), [условия камеры и ограничения](../stock_extra_dim_locked_20261118/result.md).

- **Варьировалось** только штатное включение Extra Dim (ключ отсутствует → 1 → отсутствует). Сила 50 фиксирована. Активация сервиса, RBC и общая RGB-диагональ SF **1 → 0,522 → 1** — связанные наблюдения тракта, НЕ три независимых фактора. Матрица без межканальных членов, alpha=1.
- **Удерживалось/наблюдалось отдельно:** ручная уставка 105, политика DIM, native brightness 828, actual_brightness 0, DC 0, SF 120 Гц, без HDR. В четырёх снимках не менялись остальные записанные поля; программный уровень и native DBV не зондировались независимо в этой серии. Это **confirmed-on-target** для сохранённых программных значений. Коэффициент матрицы не означает 52,2% светового потока.
- **Камера и свет:** первая серия предусмотрела 9 фото, сделано 7, оптических сравнений принято 0 из-за дрейфа ISO. Во второй 9/9 сохранённых фото дали медианы доли ярких пикселей фиксированной полосы фотографии прибора 0,610 / 0,091 / 0,537 (**confirmed-other-device**, одна серия, не три независимых опыта); физически квалифицированных A/B — 0. Оптическая связь, средняя яркость, глубина и период **unknown**. Следующий различающий контроль — независимо измерить линейный световой поток с тёмной опорой и сравнить с серым OFF при том же DBV, а не считать расчётный код серого фотометрически подобранным.

### R069. Пересекает ли штатный ручной SDR порог GLOBAL APL?

Критерий: различать порог выбранного DT, строгость реального сравнения, предел политики и фактический native readback. [Свойства DT](../device_tree/selected_boe_v4/), [дизассемблированная функция, 0x1b5a64–0x1b5a8c и 0x1b5afc–0x1b5b04](../brightness_policy_recon_20261107/evidence/dsi_panel_set_apl.txt), [архивная проверка условий 18 ноября, 21:10–21:11 UTC](../stock_apl_reachability_20261118/result.md).

- **reported, проверено по файлам:** threshold 16000, максимум класса 16180, APL-enabled; unsigned threshold ≥ входной DBV ведёт не в ветку ON. Первый возможный код включения 16001, но ещё действуют проверки уже установленного состояния и Dolby. Присвоение программного состояния предшествует обработке результата отправки. Наличие ветки или строки лога не доказывает переключения панели.
- **confirmed-on-target по прежнему отчёту:** ручной SDR/BRIGHT, HBM off, без HDR-слоёв, native 6879 до и после. Пара текущего framework-потолка и его нормализованного backlight: 0,86662334 → 0,87007874. Простая нормировка даёт round(0,87007874 × 16180) = **14078**, на 1923 кода ниже 16001. Это расчёт, **не readback на потолке**; отсутствие HDR-слоёв не считывает внутренний Dolby gate.
- Целевые коды 16000/16001: план 2, реально подано/прочитано 0/2, оптических сравнений 0. В этой конфигурации оснований считать переход достижимым нет; точный hardware-предел, другие режимы и их оптика **unknown**. Следующий различающий источник — уже имеющийся или будущий разрешённый readback native при независимо подтверждённом штатном потолке с теми же флагами, без обхода ограничений. Сам опыт на границе **HOLD**, архивный аудит завершён.

Для R069 динамические числа извлечены из текстовой сводки preflight, а не перепроверены по приватному dump; статический порог читается непосредственно из бинарного DT. Для R067–R068 это независимое сопоставление записанных полей, не повторное извлечение сырых DSI или пикселей и не новая репликация на железе.
