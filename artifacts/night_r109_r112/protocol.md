# R109–R112: архивная сверка решения

До пересчёта: проверить, выделяются ли именно фотографии состояния 3600:OFF среди четырёх состояний в опубликованной матрице, а не просто показана одна удачная медиана. Вопрос не о причинности и не о физической частоте. База анализа 77a5a78 (origin/main при создании); вход — [публичный групповой CSV](../scope_dc3601_divergence_20261118/matrix.csv). Это вторичный анализ двух старых сессий, не независимая репликация. Исходные приватные фото не читаем. Новых физических слотов: 0 запланировано, 0 снято, 0 принято. Ни устройства, ни оснастку не трогать.

Для каждого из 4 состояний X и каждого из 7 заранее опубликованных вариантов порога/сдвига ROI: вычислить минимальное Dmin среди трёх пар X↔другое минус максимальное Dmax среди **всех** остальных пар, включая X↔X. Проверяем, отделимы ли фото этого состояния от всех прочих при сильном правиле «каждая пара». Равенство не считается. Состояние выделяется по этому правилу, если минимум зазора по семи вариантам строго положителен. Обратный вывод неверен: отрицательный зазор не устанавливает физического равенства. Сравнить все четыре X симметрично, не выбирать вариант ROI по результату. Проверить уникальность, полноту и объём клеток; сохранить отрицательные результаты. Все сравнения делят наблюдения; ни p-value, ни доверительный интервал из числа пар не вычислять.

R110: раздельное решение для readback, изменения фото, основного оптического периода/его направления, огибающей, относительной глубины и индивидуального комфорта. R111: сверить формулировку в очереди с тем, какие параметры действительно измерены; не предлагать активировать профиль. R112: назвать ближайший материал и единственное допускающее событие для выбранной ветки (не для всей программы). Сверить последний **архивный** возврат, явно сказать, если актуальное состояние не проверялось.
