# Inactive held-server/held-channel observation collector

## Concrete supported interface and ownership

Collector constructor verifies exact source buffers and externally supplied expected config hash/pin values before accepting ownership of one already-connected original FixedLoopbackSocket. It has no socket factory, connect, send/recv, daemon, target selection or protocol request API. Caller must independently own that prebound socket and supply its expected FD/device/inode/owner/mode/local/peer tuple; new observations never become expected pins. Constructor rejection leaves ownership with caller. After construction, supported public operations are acquire(deadline), observe() once, and close(). Read-only state and deeply detached report snapshots cannot reset gates; all mutating/I/O helpers are private. Reinitialization and consumed/terminal replay are rejected. This is an ordinary Python API boundary, not hostile reflection protection or protection from malicious injected dependencies.

acquire opens the expected server through reader03, checks its expected starttime, and binds only that server stat path through the reviewed sticky shim. Other original LinuxAssociation operations retain their original dependencies/predicates. The exact original association body runs, including complete visible leader scans, namespace/listener/UID/executable checks and error propagation. No vanished process is skipped. Each snapshot also executes the exact reviewed address/held/custody helper function bodies extracted from the fixed3aa5265d source; those predicates are not rewritten. One bound stat check after those snapshots supplies another pidfd nonready bracket. The expected accepted inode must match across acquire/observe; no replacement channel is created.

There is one externally supplied absolute budget, checked to be positive and at most12s at acquire. observe cannot renew it. Local monotonic brackets label the snapshots. Any guard/error/denial/source or identity mismatch ends the collector and attempts owned cleanup; subsequent public acquire/observe perform no I/O. Original exceptions propagate, with a bounded8-node cause-preferred type/errno chain recorded without paths/messages/tracebacks. That chain is not a complete exception graph. Close errors, unknown pre-existing wrapper close latch and late cleanup raise and are retained; no close retry. If wrapper.sock was replaced, only the original cached owned raw object is closed, never the replacement object; the mutation still remains terminal. All comparisons rely on exclusive caller FD/object ownership, not hostile concurrent close/dup safety.

## What emitted facts actually support

- source_hashes/config_sha256: supplied source buffers and frozen expected configuration matched hashes; no values were learned-and-approved from proc observations. Dependency Python objects are trusted injected composition inputs in this inactive API. A future same-buffer loader must bind those objects to these checked sources; this artifact does NOT independently authenticate arbitrary supplied module objects and has no live envelope.
- server_pid_object_nonready_bracket: reviewed held PID-object/process-lifetime checks completed under the external authenticated-proc/numbering/namespace prerequisites. It is not immutable task_struct/executable identity across exec/de_thread.
- client_identity_sample_match: the same wrapper/raw object and sampled held FD metadata/tuples matched the caller's expected prebound object. This is local ownership/snapshot evidence, not authenticated remote identity or continuous kernel custody against hostile FD manipulation.
- original_executable_snapshot_match: original association sampled executable path/stat/digest/UID predicates successfully. executable_continuity remains false.
- original_visible_leader_holder_snapshot_match and accepted_inode: original listener scan and accepted-connection helper matched visible leader FD snapshots, within original ceilings. holder_continuity and unique_holder_qualified remain false; nonleader/private FD tables and atomic ownership are not proved.
- close-return fields record specific call returns only. If reader already closed itself on failure, a later idempotent close return does not prove prior raw closure. Reader errors/last_error and uncertainty fields remain available.

No observation is fed to a custody/admission reducer. root_authenticated/recovery_admitted remain false. Existing child NSpid evidence is not reused as server root authentication. Full route, backend/device binding and independent recovery remain unqualified.

## Bounded trace limitation

Repeated original scans can exhaust the unchanged reader03 prefix128 even during successful guard completion. The collector never clears that journal or raises its cap. It retains dropped count, logging_failed, last_error and trace_complete=false. A dropped prefix means no full raw syscall replay and no absence-of-denial inference from missing events. Guard-completion facts remain distinct: every actual reader/association error still raises and ends the collector; last_error is retained even after prefix saturation. Logging failure or recorded uncertain handle close stops. Initial tests that incorrectly treated every dropped prefix as a close failure are preserved in tests_initial.txt; no production/source guard was relaxed to handle truncation.

## Offline coverage and remaining admission gates

Eight grouped tests normal/-O use actual committed reader03/shim/LinuxAssociation/FixedLoopbackSocket and exact helper AST, with fake proc/OS/raw socket only. Tests exercise acquire/observe/close, source/config mismatch before ownership, executable/holder/denial/PID/namespace/deadline/socket-FD failures, consumed replay, public mutation/isolated report copies, raw close error/lateness, server close uncertainty, wrapper-close-latch uncertainty and wrapper-object replacement without closing the foreign object. The one fake connect belongs solely to fixture setup before collector ownership; collector makes zero connect/send/recv calls. No real proc, child, socket, server or device action occurred.

The next scope, if assigned later, must specify independently approved root/config/client provenance, qualified module-object loading, exact cleanup responsibility and raw evidence retention before any real observation. This artifact does not prepare a real host sample or install production hooks. All original pins/source remain unchanged; server/target/camera recovery and stock remain HOLD.

## Revision02: conservative cleanup uncertainty

Revision01 remains frozen, including its reporting defect: after saturated trace and an uncertain stat close, the final reader_terminal event could replace last_error while the stat_close error was dropped. An idempotent Held.close return then lacked the necessary uncertainty flag. Revision02 changes only collector reporting: incomplete reader trace plus a retained reader error or active-operation terminal event sets server_cleanup_or_evidence_unknown and a reason that lost close failure cannot be excluded. This is uncertainty, not proof that a close failed. Original error propagation, terminal guard, reader03 cap and cleanup attempts are unchanged. Successful saturated traces alone do not become operation failures.

The supported API distinguishes active acquire/observe body failures (terminal) from an observe-before-acquire order rejection (non-consuming, zero I/O). Constructor failure leaves caller ownership unchanged. Two new grouped regressions cover the exact lost stat_close error and successful saturation/order rejection; the original eight grouped tests remain unchanged.
