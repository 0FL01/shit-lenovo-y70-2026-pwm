# ILI97701A v4: что в действительности покрывает архив

**Первый байт чтения `FE` совпал с номером всех 19 выбранных stock-страниц. Новых страниц это не обнаружило.** В S5 нет ни одного сохранённого ответа; специфичность FE для неиспользуемых номеров неизвестна. Четыре завершённых широких дампа — четыре состояния яркости/refresh с `panelDC=0` перед чтением, а не четыре полные карты PWM/DC × refresh.

Живое дополнение: [R40, stock 1024 / обычные 120](../ddic_r40_page02_20261121/result.md). `02:FE` при MRPS3 вернул **long с WC3**, `02 00 00`, а не предписанный short1. После одного запроса — останов и совпавший контроль `23`. У `02` появилось наблюдение транспорта, но независимой тройки `80/82/BA` нет: к 19 различимым архивным страницам банк **не добавлен**. Остальные неизвестные ID в R40 не выбирались.

`confirmed-on-target` — происхождение сохранённых чтений XT2611-1, GLOBAL `W3WWS36.65-64-4-1`, BOE `cmd_v4`; `reported` — приведённый ниже пересчёт. Из корня worktree (Python 3, только чтение локальных файлов):

```sh
dir=artifacts/ddic_page_map_20261120
python3 -B "$dir/analyze.py" --r22 ../../private-bench-evidence/r113-20261119/r22 | diff -u "$dir/observations.txt" -
```

Без `--r22` доступна вся публичная часть. [Полный результат](observations.txt) содержит счётчики, сигнатуры, все устойчивые различия трёхбайтового префикса и упорядоченные ID. Приватные исходники остаются в каталоге стенда. База Git: `9a100d4fa5fc42a97cc9ad8cc27c024e4fdd3a0d`.

### Проверка FE и ложные совпадения

- [S1–S4](../ddic_regdump_20261107/): 38 912 строк `R`, по 2 прохода × 19 страниц × 256 opcodes на состояние. Набор страниц независимо совпадает с селекторами в [выбранном DT](../device_tree/selected_boe_v4/). **152/152** наблюдений `FE[0]==page`, из них **144/144 на ненулевых страницах**. Это повторы на одном аппарате. В каждом `raw.txt` строки FE для страницы с нулевым индексом `i` в заголовке: `256+512*i` и `512+512*i`. 40 запрошенных байт — не подтверждённая длина ответа и не последовательность адресов.
- Независимый формат R22: **2/2 PWM и 7/7 DC**, тоже на уже известных страницах. Пример для проверки: `r22_p23_0F_dc.txt:16`. S0 — 36 узких чтений, без FE. В отдельном сорванном S1 есть одно тривиальное `00:FE=00`, 424 ответа и 9304 ошибки. Не смешиваем эти попытки с завершёнными. [S5](../ddic_regdump_20261107/s5_census_dbv3584_120/run.json#L141-L159): только `run.json`, 20 событий, последним подготовлен список opcodes; ни `raw.txt`, ни таблицы, ни результата чтения в stdout, ни finish. **Выполненный устройством объём неизвестен; архивное покрытие S5 равно нулю.**
- FE — **единственный** opcode, удовлетворяющий равенству на всех 19 страницах. Но `03:C4`, `07:0C/E2`, `08:AA/DA` также равны номеру *своей* страницы во всех восьми проходах. На странице 00 есть ещё **224** opcode со стабильным первым байтом 00. `04=D2` и `0A=9C` общие у всех 19. Ни ID панели, ни ненулевой ответ, ни один ноль не различают банки. Нет отрицательного контроля «заведомо неподдерживаемый ID»; эхо последнего селектора, зеркало соседнего банка и пустой банк с работающим FE не исключены.
- Проверка независимо от FE: первые байты **трёх отдельных opcodes `80`, `82`, `BA`** образуют 19 непересекающихся непустых сигнатур (ни одной `00.00.00`), включая доступные R22-варианты; у `23` первый байт `50` либо `90`. Это отпечаток данных в выборке, не универсальный детектор отсутствия страницы. Структурная проверка `80..FD`: для примитивного блока из 2/4/6/8/12/16 opcodes, ≥2 различных префиксов (первые 6 сохранённых байт) и ≥2 значений кроме `00/FF`, стабильного во всех восьми проходах, максимальные точные повторы ≥4 найдены только на **51 и 52: 4 × 8**. На `4F:C0/C8/D0` пары первых байтов `01.06`, на `D8` — `01.10`. Ни повторов, ни чисел `06/10` недостаточно для вывода о числе оптических импульсов.

### Дифференциал: что можно разделить

| Контраст | Что наблюдалось | Граница вывода |
|---|---|---|
| DBV при 120: 3584 → 3646 (S1/S2); контроль 3584 при 144/60 (S3/S4) | `07:EC` = `2F/10/2F/2F`; `*:52` возвращает префикс DBV `0E00/0E3E/0E00/0E00` на всех 19 страницах. | Один high-DBV run; положение слайдера/контент и история не фиксированы. Не замена native DC ON. |
| Refresh при DBV 3584, порядок **120/144/60** | `*:60` = `00/01/00`; `*:58`, `2D:83`, `2D:F2` = `00/00/01`. Первые байты `2D:83/F2` согласуются с target DT `timing@0` и `@3`. `23:C1` = `000065/000055/000065`; при 3646/120 уже `000010`. | `*` — общий ответ на всех 19, не 19 находок. `1E:AE/B0`, `4F:9D/9E` меняются и при сравнении DBV, и при сравнении refresh; нельзя отнести только к одной оси. |
| R22, метки `pwm`/`dc`, 143 блока по 16 × 1 байт | PWM: полные `23/24` (512). DC: `23/4F/51/52/53/63` полные, у `24` нет `00..0F` (1776). **496 пар, 5 различий:** `23:A9`, `24:9D` `0E→8E`; `23:80` `50→90`; `23:52`, `24:52` `02→03`. | У пяти страниц вообще нет PWM-пары. Метка `dc` — состояние R22, не доказательство native DC1. В page-файлах нет per-block refresh. Изменился и префикс `52`; весь diff нельзя приписать DC при равном DBV. У `23:C1` первый байт одинаков; отдельная R23 ret/apply-пара при `00:52=0200` показывает `0002BE→000010`, не добавляя клеток в R22. |
| Native DC0→1→0 при DBV 3584/120, [15 адресов](../ddic_regdump_20261107/stock_latch.json) | Три core-поля обратимы как в R22; `53:95` = `00A0/4450/00A0`, `4F:81` = `06/10/10`. На отдельном 120→30→120→DC-cycle: `4F:81` = `10/06/06/10`. | Наличие последействия режима; native DC и трёхзаписный профиль не идентичны. |

Итого: из 4864 адресов 45 различаются при устойчивом первом байте (11 неповторяемых исключены); по первым трём байтам — 65 (12 исключены). Нет полного скрещивания двух refresh и двух PWM/DC-состояний при одном DBV. **90 Гц в широких S1–S4 нет.** При 90/120/144 и DBV 3600 есть [квалифицированный `23:C1` WC3](../c1_live_20261108/) = `000080/000060/000050`. [R21, §2](../ddic_round21_stability_20261119/result.md) сообщает о сохранении core при **четырёх** refresh 60/90/144/120; это точечные guards, не четыре дампа на страницу. Физическая частота и её регистр — `unknown`.

### Как закрывать пробел

1. **Очередь для проверки по документам/новым разрешённым архивам** — дополнение к 19 наблюдавшимся ID. В `[00,7F]` осталось **109**: `02` ([старый ILI97701A v2](../ddic_table_format_20261107/result.md#L65-L72)), `4E` ([DC-таблицы ILI97680A v1/v2](../cn_panel_commands.json)), затем `22 25 50 54 62 64` (только числовая близость к известным selector/table-страницам), затем 101 по возрастанию. Оставшиеся **128** ID `80..FF` вне даже *предложения* S5. Родство и близость — `hypothesis`, не доказательство поддержки и не разрешение на чтение. Проверять источники можно сразу; для переноса сырых данных разрешение не подразумевается.
2. **Предпосылка аппаратного census:** сначала квалифицировать ограниченный цикл selector/read/return с известным банком на том же пути (контроль состояния панели и конкурирующего трафика, native status, ограничение времени, возврат page 0 и независимая проверка восстановления ESD). Карта OEM была бы полезна, но не подменяет эксперимент. Рабочий путь для произвольных ID этим архивом **не подтверждён**. Не перезапускать старый S5 как есть: [после S5 ESD реально остался в симуляции](../ddic_regdump_20261107/esd_recovery_audit.json); [long40 не квалифицирует чтение](../ddic_response_framing_20261107/result.md). Короткий запрос сам по себе также не квалифицирует новый opcode.
3. При наличии такого пути — отдельное согласие владельца на точный allowlist **страница/opcode/длина**, режимы, бюджет, останов и проверенный возврат; старые разрешения не переносить. Сначала минимум: известный банк → один разрешённый кандидат → тот же банк, с независимым восстановлением page0 и проверкой штатного состояния. Эхо без воспроизводимой отличной от фона не-FE сигнатуры помечать `echo-only`; совпадение с известной сигнатурой — `possible alias`; timeout/ошибка — `unknown`, а не «пусто». Новое содержимое ещё не устанавливает семантику или writable-поле. Потеря режима/защиты/контроля — останов, без расширения списка.
4. Сетка **нового** полного дампа из плана владельца: stock `1024/120`, `4096/120`, `1024/144` и рецепт `1024/120` (DBV/Гц). Это три отдельных контраста к одной базе, не факторная матрица 2×2. Сохранить повтор/возврат, фактические DBV/refresh/DC до и после, подтверждение framing и покрытие по состояниям. Очередь владельца по аналогии с ILI97680A: `01 02 05 06 09 1C 1F 20 29 2F 49 4B 4E 71`; совпадения `02/4E` имеют дополнительные архивные основания выше. Для вывода об изменении света требуется оптический замер. Полный живой census остаётся открытым.

### Объём первого живого прохода (предложение, не исполнен)

Одна сессия на XT2611-1 той же сборки, из `stop: stock registers verified`, stock DC OFF, `BL=1024`, фактический обычный 120 (HWC 0). Начать с известного `23`, затем один кандидат `02`, затем контроль `23`. Для каждого чтения — штатный селектор `FF 5A A5 pp`, DCS read одного байта `FE`, затем селектор страницы 0; для ответившего `FE==pp` так же три **отдельных** чтения по 1 B `80/82/BA`. Требовать нативного статуса TX, свежего квалифицированного RX и `23:FE=23`, `23:80/82/BA=50/00/00` в контрольном stock-банке. Только при проверенном возврате и годных контролях — тот же проход по остальным ID `00..FF` (без повторов кандидатов); максимум 4 opcode на ID плюс контроль `23`. Echo-only, зеркало и неответ не считать обнаружением нового независимого блока.

Это разрешение **не** включает запись данных регистров, произвольный opcode-дамп, поиск ключей, образы или flash. До исполнения отдельно проверить ограничитель времени и независимый возврат ESD при обрыве на известном пути. Малые блоки (не более 8 ID), подтверждение page 0, ESD `reg_read`, BL/refresh и промежуточная квитанция после блока, не один длинный S5. При таймауте, потере режима, неоднозначном TX/непроверенном возврате — останов без слепых повторов. Возможны зависание/реинициализация дисплея; записей питания не планируется. По окончании — исходные BL/min/peak, возврат сессионного applier через проверенный wake. Один scoped ответ владельца покрывает весь этот проход с проверками и возвратом, а не каждый адрес по отдельности.
