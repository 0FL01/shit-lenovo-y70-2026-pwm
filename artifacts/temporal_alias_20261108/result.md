# Сохранённое stock-видео: временная фаза и 30-Hz alias

**`confirmed-on-target` (только для записи stock XT2611-1 камерой Pacman):**
fine-полосы меняют фазу между кадрами. **`unknown`:** физическая природа
полос, фундаментальная частота OLED и частота нового профиля. Работа только
с сохранённым видео/декодированными профилями; новых device/camera/DSI операций нет.

## Проверяемая гипотеза

Может ли изменение фазы fine-полосы между кадрами дать абсолютную частоту
вместо неопределённого перевода 93.43 *пространственных* строк в секунды
([предыдущий контроль](../optical_readout_ambiguity_20261108.md))?

Для двух stock-контролей по 75 кадров, 100 мкс/ISO1600, DBV3600/DC OFF/120,
в [исходном анализе](../exposure_notch_20261107/supported/analysis.json)
зафиксированы окна и q=1/93.43 циклов/строку. [Воспроизводитель](phase_alias.py)
использует сохранённые `profiles.npz` (5939×500, ROI `[540,190,60,500]`),
вычитает из каждого профиля полином Лежандра степени 2, применяет окно Hann
и извлекает комплексную фазу q, 2q, 3q. Затем измеряет наклон развёрнутой
фазы по **номеру кадра / 30**, а не превращает его в частоту панели. Полученные
числа и проверки alias — в [JSON](analysis.json).

| Stock окно | Наклон q по номерам кадров | Наклоны 2q / 3q | Макс. отличие encoded PTS от равномерных 30 fps |
|---|---:|---:|---:|
| 1 | 1.3363 цикла/с | 2.6666 / 3.9920 | 0.67 мкс |
| 6 | 1.3031 цикла/с | 2.6171 / 3.9339 | 134 мкс |

У первого окна фазовая согласованность после компенсации наклона составляет
**0.99800** для 1.3363, **0.99800** для 721.3363 и **0.99799** для
2161.3363 циклов/с: при практически равномерных 30 fps эти частоты
неразличимы по межкадровой фазе. Это *условные alias-гипотезы*, не измерения
OLED. Во втором окне при подстановке **encoded PTS** согласованности уже
различаются (0.99867 / 0.99248 / 0.93800), но сохранённые PTS не
квалифицированы как точные sensor exposure timestamps. Использовать их jitter
для выбора абсолютной частоты было бы недоказанным допущением. Неизвестна и
связь q/2q/3q с фундаментальной эмиссией: такой фазовый рисунок может
формировать камера/ISP или гармоники.

Дополнительная проверка исходного MP4 через `ffprobe -show_streams -show_format`:
только HEVC-video и AAC-audio streams, video `r_frame_rate=30/1`, MP4 video
`time_base=1/90000`; отдельного timestamp/metadata stream с sensor exposure
time нет. Это ограничение **данного файла**, не доказательство, что каждый
encoded PTS точен или неточен относительно сенсора.

**Вывод:** новый причинный признак — межкадровое движение записанной fine
структуры с примерно 1.3 цикла/с alias — установлен для двух stock окон,
но абсолютные Hz из него не следуют. Это улучшение анализа, **не панели**;
сохранённый A9-only panel baseline q93 ratio 0.2264067 не меняется. Для R3
нужны квалифицированная временна́я база/независимый оптический контроль и
причинный panel-профиль. A0D1C1 остаётся NOT AUTHORIZED / NOT RUN:
[точная серия и возврат](../dsi_coupled_9d_20261107/proposal.md) требуют
отдельного подтверждения, это исследование его не заменяет.
