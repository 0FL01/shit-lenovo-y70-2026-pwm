# R022–R024: допуск геометрии и границы метаданных R11

**Решение: не использовать старую геометрию как прошедшую валидацию.** Разработку вести на отдельном тренировочном наборе; R12b после раскрытия ключа нельзя использовать для настройки и затем называть новым слепым тестом. R11 даёт размеры буфера и области показа, но не соответствие «строка сенсора → пиксель скриншота».

Все три вопроса и единицы анализа заданы в [очереди](../../04-tasks/night-100.md) до этой ретроспективной обработки. База входов: d4c56fb. Ни одного нового захвата, опроса телефона или воздействия; нового возврата не требовалось. [Покадровые извлечения и матрица совместимости](outcome.json), [replay](audit.py), [тесты](test_audit.py).

**R022 / DONE.** Критерий: не переносить фиксированный метод как валидированный при отказе исходного полного допуска; локальная геометрия и сигнал проверяются раздельно. Из [18/18 слотов R12b](../night_r016_r018_20261118/result.md) ничего не исключено. Для 15 кодовых: оба условия проходят 6, только сигнал не проходит 6, только геометрия не проходит 3, оба не проходят 0. На трёх равномерных плашках прошли оба; они не входят в знаменатель кодовых. У трёх геометрических отказов провалилось только первое из двух окон-свидетелей: дважды NCC <0,90 и один раз dx=3 при допуске |dx|≤2 ([первичный разбор](../stock_blind_static_r12_20261118/geometry/actual_result.md)). Отсюда не следует, что телефон сместился, или что новая геометрия устранит шесть других отказов. [0/1 полных серий](../night_r019_r021/result.md), хотя признаки действительно различают коды. Статус: `confirmed-other-device` для результатов декодирования превью, причина и переносимость — `unknown`. Следующий различающий тест: подобрать устойчивые независимые метки и отдельно проверить запас по сигналу на тренировочной сцене; зафиксировать окна, пороги, критерий всей серии и контроль до получения новых скрытых масок. Не выкидывать старые отказы и не повторять зависимые прогоны как независимые.

**R023 / DONE.** Вопрос: какие ориентации и размеры явно записаны для короткой Expert 0,6×? Критерий: только актуальный конфиг Activity камеры, рамка render_frame, заголовок PNG, dynamic и static именно id2; не принимать legacy `rotation: 0`, имена доступных тегов или цветовую матрицу за матрицу изображения. План и факт: четыре коротких слота R11, 4/4 комплекта dump + UI + PNG доступны, 4/4 приняты, отбраковано 0. Все четыре дают:

- Activity: портрет, `mDisplayRotation=ROTATION_0`; app bounds (0,0)–(1080,2392), сам PNG 1080×2392. Локальная рамка render_frame (0,261)–(1080,1701), т.е. 1080×1440. Прямоугольник виджета не доказывает, как он заполнился текстурой.
- Static id2: sensor.orientation=90°, active array (0,0)–(3264,2448); latest result сообщает такой же crop. SurfaceTexture производит буферы **1440×1080**, не 1080×1440. Предмет съёмки — неподвижная плитка Lenovo, служебные значения описывают Nothing.
- `confirmed-other-device`: эти четыре согласованные записи и размерности. `hypothesis`: четверть оборота без дополнительного кадрирования могла бы согласовать размеры. `unknown`: фактическая композиция поворота/отражения, знак и ось считывания на экране, crop/поля/масштаб, деформация ISP и соответствие sensor frame → UI. Даже запись vendor «transform not changed 0» в debug-журнале AppRequestUtil (short3) не есть матрица от сенсора до дисплея. Рамка и PNG не оптические часы. Следующий различающий тест: исходный буфер и показ того же кадра с известными несимметричными ориентирами; один снимок UI не заменяет такую пару.

**R024 / DONE.** Вопрос: какие размеры [публичных режимов GC08A8](https://github.com/NothingOSS/android_kernel_modules_nothing_mt6878/blob/65ef638c5c49dddf78f5b48edddd44786d705197/mtkcam/imgsensor/src-v4l2/common/gc08a8_mipi_raw/gc08a8mipiraw_Sensor.c#L108-L242) совместимы с конкретными stream R11? Критерий: точно равные стороны, одинаковое отношение сторон с равномерным масштабом или требуется изменение компоновки/геометрии. Сравнены 3/3 активных записи mode_struct с 5/5 выходами тех же четырёх конфигураций (не четыре независимых сценария); закомментированный шаблон не режим. Исходник проверен по [пину R12](../stock_gc08a8_timing_r12_20261118/result.md).

| Выход Nothing | Что наблюдается | prev и cap: 3264×2448 | vid: 3264×1836, y1=306 |
|---|---|---|---|
| 0 SurfaceTexture, 1440×1080 | Накопленные счётчики 1724, 2545, 3018, 3496 | Оба размера ×15/34 | Не равномерное масштабирование полного 16:9 в 4:3 |
| 1, 2, 3 ImageReader, каждый 3264×2448 | Три разных формата, 0 произведённых у каждого | Равенство размеров | Иное отношение сторон |
| 4 ImageReader, 1920×1088 | 0 произведённых | Иное отношение сторон | 1920:1088 не точно 16:9; padding возможен, не засвидетельствован |

Результат для 0: preview/capture **неразличимы** по геометрии. При допущении дополнительного crop из 16:9 в 4:3 возможен и video: например, 2448×1836 из центра → 1440×1080, масштаб 10/17. Это пример неединственности, а не восстановленная область съёмки. Равенство размеров не подтверждает RAW/один-к-одному; нечитаемые или непроизведённые выходы не свидетельствуют о выборе режима. `confirmed-other-device` для объявленных stream и накопленных счётчиков; не для соответствия установленного драйвера публичному. CUSTOM 36869 — режим сессии, не индекс сценария. В latest result нет значения тега com.mediatek.seamlessfeature.sensorScenario; объявление ключа не значение. Выбранный сценарий, реальная цепочка и физическая шкала — `unknown`. Следующий различающий источник: явный per-frame scenario с проверенной привязкой к режимам установленной сборки; без него не назначать один из трёх. Частота, глубина и снижение ШИМ не проверялись.

**Воспроизведение.** Нужны Python 3, дерево артефактов этой ревизии, исходный архив R11 и pinned C-файл из R12. Архивные raw/PNG сверены со старым манифестом R11; для UI прежнего пина в этом манифесте нет, отпечатки в outcome.json фиксируют именно версии данного replay. Переменные ниже — пути у проверяющего:

    python3 -B audit.py "$R11_ARCHIVE" "$GC08_SOURCE" | cmp - outcome.json
    R11_ARCHIVE="$R11_ARCHIVE" GC08_SOURCE="$GC08_SOURCE" python3 -B -m unittest -v test_audit
    R11_ARCHIVE="$R11_ARCHIVE" GC08_SOURCE="$GC08_SOURCE" python3 -OB -m unittest -v test_audit

С оригиналами по 4/4 теста и байтовое сравнение прошли. Без переменных три публичных теста и один явный SKIP. Фотографии, закрытые полные дампы и абсолютные аппаратные ID не публикуются.
