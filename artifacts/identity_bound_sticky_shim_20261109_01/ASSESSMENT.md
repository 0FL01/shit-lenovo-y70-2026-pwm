# Inactive sticky-error bridge for reader03

Exact reader03 (658edfc7) must be explicitly loaded as identity_bound_reader_revision03; the shim accepts only that exact Held class. No default acquisition, adapter, source discovery or loader installation is provided. The dependency parameter is the actual committed linux_adb_probe_dependencies module from the frozen combined fixture in tests, not a reimplementation.

StatShim.read supports only the already-held process's exact planned /proc/PID/stat request and fixed16KiB cap. That string is an interface match, never a numeric filesystem reopen. The operation delegates to Held.read_stat once. Any new logical/identity/unknown error maps to ProbeError(trust_invalidated=True) with the genuine original object retained as cause/context; actual safe_errors then applies its unchanged sanitizer. Already-invalidating ProbeError is bare-raised inside the mapping. Only owned handle cleanup is attempted after failure; no alternate read, reset, re-pin or retry. Public terminal/held properties cannot be reassigned and constructor replay is rejected.

KeyboardInterrupt/SystemExit retain their original objects and propagate while the reader/shim become terminal. The inactive association_type subclass wraps the ACTUAL LinuxAssociation.__call__ only to set its sticky flag when such interrupts escape; the original body/sanitizer is otherwise unchanged. This extra wrapper is necessary because the old association deliberately passes interrupts through without necessarily marking sticky. No production class/loader is patched, and this stronger composed interrupt contract is not attributed to old behavior.

Four grouped fake tests normal/-O cover success, wrong request/cap, ENOENT/ESRCH/EACCES/EPERM/EIO contexts, logical identity/namespace/deadline/cap errors, unknown RuntimeError and original interrupts. Actual safe_errors and actual LinuxAssociation methods are executed. Association failure integration substitutes one synthetic stat stage (fixture PID101 request delegates to fixture held PID42) solely to exercise failure propagation; it is explicitly not real PID mapping/physical identity proof. Other association reads use existing fake proc fixture. On every mapped failure/interrupt, association trust_invalidated is true and the next call has no reader fake I/O. No production, host, child, proc or socket observation occurred.

This is a narrow bridge, not full ProcFS coverage. Future integration must bind each actual stat request to the correct independently acquired handle, preserve complete no-skip process scans, publish the new source closure and qualify root/proc-numbering/namespace and handle ownership. No executable immutability, channel/holder custody, arbitrary nonchild binding or recovery route follows. The same-PID namespace prerequisite cannot be inferred from self/ns/pid alone. Reader03 public API restrictions exclude deliberate private reflection; they are not a sandbox against malicious Python. Root/target/camera recovery and stock remain HOLD.
